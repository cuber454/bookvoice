# План: обычное чтение — голосом движка (согласовано с Сержем 24.10.2026)

Записано по итогам разговора 23-24.10.2026. **Код ещё не менялся** — сборка только
по слову «собирай».

## 0. Что решили

1. **Способ чтения меняются местами.** Обычным становится прямой путь — текст
   отдаётся движку, он сам синтезирует и говорит. Файловый (синтез в файл →
   ExoPlayer) становится обходным.
2. **Строка в «Чтении»** называется «Читать файлами (обходной способ)», по
   умолчанию **выключена**. Названия «Альтернативный способ чтения» больше не
   будет: альтернативным стал файловый путь.
3. **Миграция настроек не переворачивает смысл старого ключа.** Заводим новый
   ключ (по смыслу «читать голосом движка», по умолчанию — да). Старый
   `alt_direct_voice` читаем только для миграции и **не удаляем** (чтобы откат на
   прежнюю версию не сломал настройки):
   - старого ключа нет (человек галочку не трогал) → новое умолчание, движок;
   - старый ключ = включён → движок (это его собственный выбор);
   - старый ключ = выключен (человек сам снимал, выбирал файлы) → оставляем
     файлы, в журнал пишем «оставил прежний выбор».
4. **Профили движков (`expert_force_<пакет>`) не меняются** ни в числах, ни в
   смысле: меняется только смысл «сам по опыту» — теперь это «сначала голосом
   движка». «Только файлом» остаётся файлами.
5. **Роли (реплики вторым голосом) — тоже голосом движка.** Способ один для всех.
   Цена, принятая сознательно: на смене роли слышен стык (голос применяется перед
   фразой). У @Voice та же беда записана в их changelog («при смене движка пауза
   между предложениями игнорировалась», 25.6.2).
6. **Пауза и продолжение.** Допустимо, что продолжение перечитывает текущую фразу
   с начала: у TTS нет позиции внутри фразы. Чтобы повтор был коротким —
   **резать склеенную фразу на части-предложения и помнить номер части** (механизм
   частей уже есть, им гоняются слова автора и реплика). Тогда «продолжить»
   перечитает текущее предложение, а не всю склейку.
   КАК У @VOICE (уточнено 24.10.2026): движку уходит **одно предложение за раз**, а
   следующее ставится сразу за ним без остановки — для человека это ровная речь.
   Место в книге и ключи остаются на фразе, склейка коротких предложений остаётся
   ТОЛЬКО в файловом пути (там файл на предложение дорог и стыков больше). Если на
   какой-то паре стыки между предложениями станут слышны — возвращаем склейку этой
   паре по журналу.
7. **Сбой голоса — не останавливаемся, уходим на локальный голос** (как @Voice).
   Ступени:
   1) не расслышали/молчит — повторяем фразу (механизм `noteSilentPhrase` есть);
   2) не помогло — сами ставим **локальный голос того же движка**;
   3) у движка локального голоса нет — **локальный голос другого установленного
      движка**;
   4) файлы — **последними**: либо движок отказывается говорить, но файлы отдаёт
      нормально, либо человек сам включил «Читать файлами».
   Каждую подмену объявляем словами вслух: «Голос не отвечает. Читаю другим
   голосом: …» — иначе человек слышит чужой голос и не понимает, что произошло.
   Помним подмену **до перезапуска приложения**, потом снова пробуем выбранный
   голос (у @Voice это галочка «Revert to local voices when app is restarted»).
8. **Запас вперёд — 2–3 фразы, а не «по одной».** Основные паузы в прямом чтении
   даёт не сбой, а пустая очередь: если у движка в руках только текущая фраза,
   стык слышен на каждой. «Одна фраза» остаётся страховкой для пар, помеченных
   «врёт про „доиграл“». Начать с двух, по журналу поднять до трёх.
9. **Кнопки гарнитуры — три отдельные правки** (разбор — ниже, раздел 3):
   тишину отдавать движку, объявить приёмник `MEDIA_BUTTON`, забирать кнопки назад
   после потери аудиофокуса.
10. **Свой «тихий поток» по умолчанию выключаем** (решение Сержа 24.10.2026) — но
    только ПОСЛЕ того, как заработает тишина от движка: два источника тишины не
    нужны, гарнитура на них путается. Строка настройки остаётся ручным
    выключателем; в «Что нового» пишем словами, что включать её больше не надо.
    ЕСЛИ движок не поддерживает `playSilentUtterance` — поток возвращаем сами и
    пишем причину в журнал.
11. **С сетевыми голосами — сразу прямой путь, файлы не пробуем вовсе**
    (решение Сержа 24.10.2026: «чтобы читалось всё точно так же, как у @Voice»).
    Прежняя проба «а вдруг файл придёт» (два пустых файла подряд → пометка пары)
    для сетевых отпадает: у @Voice такой пробы нет. Сроки остаются увеличенные
    (`SLOW_TIMING`), заявок в работе несколько. Повтор фразы = новый запрос в сеть
    (деньги — только у платных голосов, их у нас нет). Кэш звука возможен лишь там,
    где движок файлы отдаёт (сетевые голоса Google), — это идёт вместе с записью
    «Кэш звука для платных голосов» в `docs/BACKLOG.md`. Свои облачные движки
    @Voice (Azure, Polly, OpenAI по ключам) не копируем — это отдельная работа.
12. **Выбор человека сильнее пометок.** Если строка «Читать файлами» включена (или
    у движка профиль «только файлом»), автоматика НЕ уводит пару на голос движка:
    пометки пары остаются пометками, работаем по выбору человека. Иначе человек
    выбрал один способ, а приложение молча ушло в другой. При выключенной строке
    пометки работают как раньше — могут увести пару на файлы там, где движок файлы
    отдаёт нормально.
    ИСКЛЮЧЕНИЕ (решение Сержа 24.10.2026: «если файлов не даёт — никаких других
    вариантов не остаётся, тогда зачем спрашивать»): если движок файлы физически
    не отдаёт, выбора нет — переключаем на голос САМИ и объявляем словами:
    «Этот движок файлов не даёт. Читаю голосом.» Пометка «не отдаёт файлы» из
    переключателя способа превращается в объяснение причины (обычный способ теперь
    и так голосом, решать ей нечего).

13. **Пометка «не отдаёт файлы» ставится ТОЛЬКО в файловом режиме** (уточнено
    24.10.2026 после отмены пункта 22). В обычном чтении файлы не заказываются
    вовсе, значит и помечать нечего. Если человек включил «Читать файлами» и движок
    отдал два пустых файла подряд — ставим пометку навсегда, переключаемся на
    голос, говорим об этом словами. Стёрли пометку («Забыть пометки движка») —
    в файловом режиме снова попробуем файлы, там и увидим, починили движок или нет.
14. **Сетевые и локальные голоса одного движка — решаем ПО ПАРЕ «движок + голос».**
    Провал голоса помечает только его; правило «два сетевых голоса движка
    провалились → все сетевые голоса этого движка голосом» остаётся, локальные не
    задеваются. С учётом решения 11 (сетевые сразу голосом) вся эта логика теперь
    нужна только для ЛОКАЛЬНЫХ голосов, которые файлов не отдают.
15. **Скорость и тон на ходу — как сейчас** (решение Сержа 24.10.2026): перечитываем
    текущее предложение новым темпом (estartDirectForRate уже так делает), место
    не двигается.
16. **Реплика, а второй движок не ответил:** читаем реплику ГЛАВНЫМ голосом и
    говорим об этом словами (решение Сержа 24.10.2026). Молча подменять голос
    нельзя: человек услышит не тот голос и не поймёт почему.
17. **Карточка в шторе:** позиции в звуке у голосового чтения нет, поэтому полоску
    прогресса не показываем — показываем главу и процент (решение Сержа 24.10.2026).
18. **Громкость:** в файловом пути есть усиление, в голосовом нет — звук может быть
    тише. Принято (решение Сержа 24.10.2026); усиление >100% остаётся параметром
    громкости движка.
19. **Паузы внутри предложения** у сетевых голосов (0,5–1 с) в голосовом чтении НЕ
    срезаются — это звук движка, не наш. Чтение будет «с передышками», как у
    @Voice. Принято (решение Сержа 24.10.2026: менять нечего, спрашивать не о чем).
20. **Кнопки гарнитуры:** гипотезу «тишина от движка» (playSilentUtterance) нужно
    СНАЧАЛА проверить на телефоне — это может быть не наш случай (у @Voice так
    держат кнопки, когда играет их кэш, а не движок). Без проверки можно потратить
    работу зря. Решение Сержа 24.10.2026: «кнопки там точно теряются, делай сразу» — делаем, а на телефоне проверяем уже результат (журнал + поведение кнопок в голосовом чтении).
21. **Скрытой ручки «вернуть файлы по умолчанию» НЕ добавляем** (решение Сержа
    24.10.2026: «если что, соберём потом просто новую версию»). Откат, если новый
    способ где-то окажется хуже, — обычная правка и новая сборка. Опытные настройки
    новыми строками не растут.
22. **Попытки «читать без пауз» НЕ ДЕЛАЕМ** (решение Сержа 24.10.2026: «я опять
    перемудрил, давай делать как у них, это не будем трогать вообще»). Ни галочки у
    голоса, ни 2-секундной пробы файла в обычном чтении нет. У @Voice такого нет:
    там всегда говорит движок, файлы только для записи и кэша облачного звука.
    Пункт 22, где предлагалась проба на 2 секунды, ОТМЕНЁН.
    Следствие: паузы внутри фразы (0,5–1 с у сетевых) остаются как есть (пункт 19),
    обрезка тишины работает только в принудительном файловом режиме.
## 0а. Настройки: что меняется, а что нет

Меняется смысл (строка остаётся):
- «Альтернативный способ чтения» → **«Читать файлами (обходной способ)»**, по
  умолчанию выключена;
- «Тихий звуковой поток» → по умолчанию **выключен** (тишину даёт движок);
- «Пауза между фразами» (обрезка тишины при сборке файла) — работает ТОЛЬКО в
  файловом способе, подпись поправить;
- «Проверить движок» — вопрос «даёт ли файлы» теперь только про обходной путь;
- профили движков: «только движком» совпадает с «сам по опыту» — переименовать в
  «всегда голосом, даже если врёт»;
- «по одной фразе» — руками больше не нужна (это делают ключи и пометки), остаётся
  страховкой.

Прибавляется (за дверью, в опытных настройках): срок ожидания сетевого голоса
(15 с по умолчанию), число повторов (1…10), «только по Wi-Fi».

Не прибавляется: кэш звука (ждёт платных голосов), облачные ключи, запись в файл.

Прокрутка — ДВЕ строки свести в ОДНУ (решение Сержа 24.10.2026: «очень много
настроек получается»):
- «Прокручивать экран за чтением» (KEY_SCROLL) и «Читать с того места, куда
  прокрутил» (KEY_SCROLL_PLACE) убираются;
- вместо них одна строка **«Где держать читаемое предложение»** со значением
  «сверху» (как сейчас) или «по центру» (как у @Voice, их «Center the current
  sentence on the screen»). Правка — в MainActivity.alignSentence: при «по
  центру» смещаем на половину высоты ленты;
- следствия, принятые Сержем: прокрутка всегда идёт за чтением (выключить, чтобы
  осмотреться, больше нельзя) и место чтения всегда переходит туда, куда прокрутил
  человек (как было по умолчанию).
- слово «фокус» в названии не используем: у диктора фокус — своё понятие.
Ничего не удаляем до пробы (решение Сержа 24.10.2026): сначала поправить подписи,
после журналов убрать то, что реально не нужно.
## 1. Что для этого уже есть в коде

- Прямой путь после переделки в пробе 258 работает на тех же ключах, что файловый:
  заявка несёт `(текст, pos, part)`, опознаётся `Pending.key`, `reportDone` идёт с
  местом, `playedKeys` наполняется и в прямом пути, запас считается фразами
  (`directPhrasesAhead`). Разбор — `docs/REVIEW-reading-duplicates.md`, разделы 10
  и 15.
- Решение «каким способом читать» уже вынесено в `decideDirectMode` /
  `switchPipeline`, причина словами — `SpeechPlayer.directWhy` + `ReadingMode`
  (`short()` в строке, `long()` вслух), поэтому смена умолчания не требует новой
  логики решения — только другого входа в неё.
- Пометки опыта уже живут по паре «движок + голос» (`marks` / `putMarks`):
  «не даёт файлы» (`direct_synth_marks`), «медленный», замер первой фразы. Нужна
  обратная пометка — «не говорит» (движок молчит или врёт про «доиграл»), чтобы
  пара запоминалась и на ней работала следующая ступень.
- Строка «Каким способом читаю» и вторая строка у галочки уже объясняют живой
  способ словами — новый смысл надо просто переписать.
- Подмена голоса уже умеет менять голос на ходу (`selectVoice`), чистка старого
  голоса — `dropPrepared()`; прогрев — окно `armVoiceWarmup`. Смена голоса стоит
  одну паузу (6–12 с прогрева), а не паузу на каждой фразе — потому она и лучше
  отката на файлы.

## 2. Чего сознательно НЕ делаем

- Не смешиваем способы внутри одного чтения: файлы и движок одновременно не
  включаем (TeraTTS не пишет файлы, пока говорит сам — на этом сломались 237-241,
  `docs/HISTORY.md`).
- Не меняем versionCode и «Что нового» без отдельного слова на выпуск.
- Не трогаем файловый путь по сути: он остаётся рабочим и выключается только
  строкой.

## 3. Кнопки гарнитуры: почему у @Voice работает всегда, а у нас иногда нет

Проверено по их APK (40.9.1, `work/atvoice.apk`, dex распакован):

1. **У них своя медиа-сессия и свой приёмник кнопок.** В манифесте объявлен
   `com.hyperionics.avar.MediaButtonIntentReceiver` на `android.intent.action.MEDIA_BUTTON`,
   а в коде — `MediaSession` с `MediaSession.Callback` и `setMediaButtonReceiver`.
2. **Тишину они отдают ДВИЖКУ**, а не своему плееру: `playSilentUtterance(...)`.
   Для телефона и гарнитуры это звук от TTS, поэтому «последним играющим»
   остаётся их сессия. Наш «тихий поток» — свой, отдельный: часть гарнитур считает
   его тишиной и кнопку не отдаёт (отсюда «иногда пропадает»).
3. **Они сами забирают кнопки обратно** — в их changelog: «Trying to regain headset
   button focus after a long phone call». У нас такого шага нет: после звонка,
   уведомления или чужого плеера кнопка уходит, и мы это не замечаем.

Отсюда три правки (независимые, каждая сама по себе):

1. В прямом режиме тишину держать **движком** (`TextToSpeech.playSilentUtterance`),
   а не только своим потоком — как у них.
2. Объявить в манифесте приёмник `MEDIA_BUTTON` — страховка, если сессия не
   активна (кнопку получит приёмник, а не чужой плеер).
3. Ловить потерю аудиофокуса (`AudioFocusRequest` потерян, конец звонка) и
   **возвращать** кнопки себе, а не ждать, пока человек нажмёт «Читать».

## 3а. Сетевые голоса: схема @Voice берётся ЦЕЛИКОМ (решение Сержа 24.10.2026)

Серж: «хочу чтобы ты взял всё полностью как у них» — своя схема не выдумывается,
переносим их политику. Их схема по их же строкам ресурсов и changelog:

1. **Срок ожидания** — настройка «Network timeout (sec, 0: default)», по умолчанию
   15 с (changelog 27.2.3: «set a longer timeout than the default 15 seconds»).
2. **Число повторов** — «Retry count, if error downloading», 1…10, 0 = по
   умолчанию; повтор с паузой (changelog 28.0.11).
3. **Состояния заявки** — ждёт / ждёт повтора (`QUEUED_FOR_RETRY`, «Keep for
   retry») / прочитано. Ошибка не выбрасывает фразу из очереди.
4. **Кэш звука на диск** — «Cloud voice audio cache»: включить, сколько дней
   хранить, сколько МБ, кнопка очистки; повтор играется с диска
   (changelog 40.7.3, 40.7.4). Берём там, где движок отдаёт файлы.
5. **Провал** — сами уходят на локальный голос и говорят об этом словами
   («Trying to switch to a local voice»); после перезапуска приложения снова
   пробуют сетевой (галочка «Revert to local voices when app is restarted»).
6. **Тишина от движка** — `playSilentUtterance`, чтобы сессия и кнопки гарнитуры
   оставались нашими, пока звук идёт не от движка.
7. **Только по Wi-Fi** — отдельная галочка «Use cloud voices only on WiFi» для
   тех, кто бережёт трафик.

ГДЕ НАША СХЕМА НЕ МОЖЕТ БЫТЬ ИХ: запросы в сеть делает не наше приложение, а
чужой движок (MultiTTS и подобные) — у @Voice это их собственный HTTP-код с
ключами Azure/Google/Polly. Поэтому «повтор запроса» у нас один: повторить фразу
движку. Всё остальное (сроки, число повторов, состояния, кэш там где файлы есть,
переход на локальный голос, тишина, Wi-Fi) переносится дословно.

## 4. Как проверим

- Журнал: на старте чтения одна строка, почему читаем так — «голосом движка (новое
  умолчание)» / «файлами (выбор человека)» / «файлами (профиль движка)» /
  «файлами (движок не умеет)».
- Проба на медленном голосе (TeraTTS) и на прослойке: стыки, повторы, реакция
  кнопок гарнитуры, поведение после звонка и после паузы.
- Откат каждой правки отдельный: кнопки — тремя пунктами, режим — возвратом
  умолчания, части фразы — снятием разбиения.
