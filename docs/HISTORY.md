## Реплики: один движок — один экземпляр (29.09.2026, ещё не собрано)
- Повод: журнал 20:10 — «включено чтение по ролям, а читает одним голосом» и
  «фраза повторилась». Причина одна: `onSynthWatchdog` при первом же молчании
  движка реплик объявлял `replyBroken` и до конца сеанса читал всё основным
  голосом, а ту же фразу перечитывал им же. Плюс у Сержа оба голоса живут в ОДНОМ
  движке (MultiTTS), а мы держали ДВА экземпляра одного движка — движок теряет
  заявки (Google TTS этим и славится).
- Как делают читалки (проверено по SDK: `TextToSpeech.Engine` НЕ имеет публичного
  параметра голоса для отдельной фразы — только STREAM/VOLUME/PAN/UTTERANCE_ID,
  voiceName скрыт): держат ОДИН экземпляр и ставят голос перед заказом фразы;
  второй экземпляр — только когда вторая роль в ДРУГОМ движке.
- Сделано: `replyNeedsOwnInstance()` (движки разные?). Если движок один —
  `borrowMainForReply(t)` ставит голос реплик на основном экземпляре, фраза
  заказывается и `restoreMainParams(t)` сразу возвращает книжный голос (движок
  запоминает голос в заявке, поэтому книжные фразы не страдают). Второй экземпляр
  поднимается только для другого движка; `prepareReplyEngine` и `waitForReply` для
  одного движка не зовутся вовсе.
- Второй срок вместо отказа: `replyMisses` — первый промах движка реплик просто
  ждём ещё раз, отказываемся (`replyBroken`) только на втором подряд; счётчик
  обнуляется, когда реплика пришла.
- Никаких «толчков»: проба разбудить движок таймером убрана (и поля
  `replyWorkedAt/REPLY_WARM_*` тоже). Поднять отказавший (только чужой) движок
  пробуем по делу — на очередной реплике, не чаще раза в минуту
  (`maybeReviveReplyEngine`). Серж отдельно спросил про нагрузку на процессор и
  сам предложил внести движок в исключения по батарее — согласен, это сильнее
  любых наших толчков; из приложения чужому пакету это поставить нельзя.

## Сборка 205 (29.09.2026, отправлена Сержу): повтор после паузы
- Жалоба: «одна фраза повторилась, не пойму — дочитывал или что». Журнал сеанса
  204, 21:49:07: пауза волшебным касанием в начале репликовой фразы s_8, при
  возобновлении в 21:49:09 звучит НОВЫЙ файл s_12 того же размера (тот же текст) —
  то есть фраза синтезирована заново и прочитана С НАЧАЛА. В журнале нет строки
  «пауза: звук фразы сохранён» — значит `pauseKeepingPhrase` не сохранила звук.
- Причина: `playingRate` выставлялся только в `exoPlay` (фразы, которыми СПИСОК
  начинают). У фраз, доигранных из очереди, там оставался чужой темп, а
  `pauseKeepingPhrase` сравнивает `playingRate == rateFor(roleOfFile(file))` — не
  совпало, файл удалялся, продолжение синтезировалось заново с начала.
- Правка: в `exoListener.onPhraseStart` темп берём у самой звучащей фразы из
  зеркала (`exoPending…rate` → `playingRate`) вместе с `exoSyncSpeed`. Теперь
  пауза узнаёт фразу всегда.
- Замечание на будущее: это не следствие сноса старого плеера (условие с
  `playingRate` было и раньше), просто раньше оно срабатывало не на каждой паузе.
