# BookVoice — рабочий документ проекта

Этот файл — «холодный старт». Он для того, кто берёт проект в руки впервые
(новый человек или новый агент) и должен продолжать с того места, где
остановились, а не переоткрывать уже пройденное.

Читать по порядку. Разделы 3, 7 и 11 — обязательные: там правила, нарушение
которых стоило уже многих сборок и многих часов владельца.

---

## 1. Что это

BookVoice — Android-читалка для незрячих. Озвучивает книги через системный
синтезатор речи (TTS), управляется жестами и скринридером, экран при этом
вторичен.

Ключевое отличие от «плеера с текстом»: **единица работы — предложение, а не
файл.** Приложение режет книгу на предложения и абзацы, знает, где оно
находится, и держит связку «играет = подсвечено = прочитано диктором». Всё
остальное — библиотека, каталоги, форматы — обслуживает эту связку.

Пользователь — незрячий человек, читающий ушами и на ощупь. Он не видит
экрана: любая проверка «посмотри, как выглядит» невозможна, а любая
неозвученная перемена в интерфейсе для него не существует.

**Приложение открытое.** Репозиторий публичный, APK в релизах, у проекта есть
группа поддержки и внешние тестеры.

## 3. Железные правила работы

Это не стилистика, а то, на чём уже спотыкались.

**Один вопрос — одно сообщение.** Владелец читает ушами; несколько вопросов
подряд в одном сообщении он не удержит. То же с инструкциями: одна проверка
за раз, следующий шаг — после ответа.

**Сборка — только по его слову.** «Пока не собирай» означает буквально это.
В ветке может лежать несколько правок без сборки — это нормально. Каждый
прогон стоит времени, а тестовая сборка у него одна на все проверки.

**Каждая сборка сверяется по подписи.** APK, который не подписан тем же
ключом, не встанет поверх установленного — установка провалится, а лечится
это только удалением приложения вместе с библиотекой, местами чтения и
настройками. Поэтому отпечаток сертификата проверяется ДО отправки файла
(раздел 4).

**Никаких книг и паролей в чат.** Логин и пароль от внешней библиотеки
владелец не присылает и не должен.

**Не выдавать меру за причину.** Самая дорогая ошибка этого проекта: длинное
число (180 секунд ожидания) было принято за объяснение проблемы, хотя
объясняло только её длину; сборка ушла впустую. Числа в коде — это следствие,
корень ищется в журнале.

**Проверять, а не вспоминать.** Платформенные API не писать по памяти: метод,
которого нет в SDK, стоит прогона сборки и правки поверх уже выпущенного
релиза. Обращаться к существующему в коде API или сверять по классам.

**Не переисследовать закрытое.** В разделе 11 собраны темы, по которым
решение принято и повторный заход запрещён владельцем. Возвращаться к ним
можно только с новым фактом, а не с новым настроением.

**Имена проверять на слух.** Названия разделов и строк интерфейса незрячий
слышит, а не читает. «Интерфейс» в списке не говорит ему ничего — поэтому
раздел называется «Экран книги». Перед тем как назвать что-то, произнесите
это вслух.

**Диагностика вместо догадок.** В приложении есть журнал (`diag.log`), и он
разрешал почти каждый спор: сторож сработал или нет, дошло касание до текста
или нет, спал процесс или только движок. Собирать журнал, а не угадывать.
Признак «процесс был заморожен системой» — дыра во времени между отметками
«бьюсь»; ровные отметки при пропавшем звуке — спал синтезатор, не приложение.

## 4. Как собрать и выпустить

### Почему нельзя собрать локально

Контейнер сборки — arm64, а весь Android-тулчейн (`tools/`) — x86_64. Google
не публикует `aapt2` под linux-arm64 (проверено по maven до 9.4.0: в
linux-артефакте всегда один x86_64 ELF), эмуляции x86 нет, прав root нет.
Сборка падает на `:app:processDebugResources` с «AAPT2 Daemon startup failed».

**Локальный тулчейн не чинить — пути нет.** Единственная сборка — GitHub
Actions.

Память: cgroup ≈1,5 ГБ, поэтому в `gradle.properties` стоят ужатые
`-Xmx512m -XX:MaxMetaspaceSize=256m` и `org.gradle.workers.max=1`. Обратно не
поднимать. На CI workflow сам поднимает до `-Xmx3g` перед сборкой.

### Сборка (тест, без релиза)

```bash
cd <репозиторий>
git push origin portyanka
gh workflow run build-apk.yml --ref portyanka
gh run watch <id> --exit-status
gh run download <id> -n apk -D <каталог>
```

- **Сначала push, потом workflow.** `workflow_dispatch --ref` собирает голову
  ветки на remote, а не локальный коммит. Закоммитили и запустили без пуша —
  собралось старое. Сверять `gh run view <id> --json headSha` с нужным коммитом.
- Имя артефакта — `apk`, внутри `BookVoice-dev.apk` (без тега) или
  `BookVoice-<версия>.apk` (с тегом). Внутренняя версия берётся из
  `build.gradle.kts`, а не из имени файла.
- `gh run download` кладёт файл **в текущий каталог**, а не туда, откуда
  запускали workflow.
- Если push просит логин: `gh auth setup-git --hostname github.com`.
- Сборка из середины ветки: `git branch -f <имя> <хеш> && git push origin <имя>`
  и запустить workflow на этой ветке; после проверки ветку удалить.
- Типичное время прогона — 1,5–2 минуты, размер APK ≈16,5 МБ.

### Что делает workflow `build-apk.yml`

checkout → JDK 17 → восстановление ключа подписи из секрета → установка
platforms/build-tools android-36 → setup-gradle 9.1.0 (полная версия, «9.1»
action не находит) → правка `jvmargs` под CI → `gradle --no-daemon
:app:assembleDebug` (зовётся `gradle`, не `./gradlew`) → переименование в
`BookVoice-<версия>.apk` → upload-artifact → при теге `gh release upload
--clobber`.

### Подпись

Ключ — стандартный debug-keystore проекта, **один и тот же у всех сборок**.
Он лежит в секрете репозитория `DEBUG_KEYSTORE_B64` (base64), workflow
раскодирует его в `$RUNNER_TEMP/keystore/debug.keystore` и передаёт сборке
через `BV_DEBUG_KEYSTORE`; `app/build.gradle.kts` при наличии этой переменной
создаёт `signingConfig "ciDebug"`.

Зачем так: **AGP на раннере молча генерирует новый debug-keystore**, если не
сказать ему путь, — и тогда все обновления перестают вставать.

Отпечаток сертификата (SHA-256), он же в выпущенных APK:

```
81:B4:9C:78:8D:67:F7:06:65:09:58:06:ED:B9:96:5D:EE:1F:9E:93:C2:03:86:69:50:9C:AF:77:81:B9:4C
```

Проверка APK перед отправкой — двумя скриптами: один печатает версию из
`AndroidManifest.xml` внутри APK (искать в UTF-16LE), другой достаёт
сертификат из APK Signing Block и сверяет отпечаток через `openssl x509
-inform DER -noout -fingerprint -sha256`.

**Свой парсер APK Signing Block не писать.** Самодельный разбор выдал четыре
разных отпечатка на четырёх APK одной подписи — то есть молча врал, и свежая
сборка едва не была забракована. Проверка, которую нельзя перепроверить тем
же инструментом, — не проверка.

Если репозиторий переезжает под другой аккаунт — тот же ключ нужно положить
в секрет `DEBUG_KEYSTORE_B64` нового репозитория. Секреты GitHub не читаются
обратно, поэтому единственная копия ключа — та, что хранится вне GitHub.

### Релиз

- Тег = `v` + `versionName` (`v0.4.42` ↔ `0.4.42`).
- Релиз создаётся вручную: `gh release create vX.Y.Z --title … --notes-file …
  --target <коммит portyanka>`. APK прикрепляет workflow по событию
  `release: published`.
- **В теле релиза обязательна строка поддержки** со ссылкой на группу (та же,
  что в прошлых релизах; в коде она же — `AuthorContact.INVITE_URL`).
- Автообновление смотрит `api.github.com/releases/latest` и берёт первый
  `*.apk`-ассет — **до появления APK в релизе оно молчит**.
- Автопроверку обновлений можно выключить: в «Разном» флажок «Проверять
  обновления автоматически», по умолчанию включён (22.09.2026). Выключен —
  тихой проверки нет, остаётся кнопка «Проверить обновление»; кнопка работает
  всегда. Раньше на этом месте был выбор «Автоматически / Вручную» (0.3.91).
- У кого уже стоит тестовая сборка с тем же номером, обновление не увидит:
  чтобы обновить и их, следующий релиз нумеруется вперёд.
- Тестовые сборки (без тега) релиза не создают и автообновление не трогают.

### «Что нового»

Файлы: `WhatsNew.kt` (логика) и `whats_new_strings.xml` (тексты).

- `WHAT_NEW_SEEN` хранит **versionCode**, не versionName.
- Тексты называются `whats_new_<versionCode>_N`, и то же число должно стоять в
  реестре `NOTES` в `WhatsNew.kt`. **Разойдётся — окно не покажется никогда.**
- `hasNotes()` смотрит на ТЕКУЩИЙ versionCode: если под текущую версию блока
  нет, пункт «Что нового» исчезает из «О программе» совсем.
- Тексты читаются вслух — писать фразами, без эмодзи (синтезатор произносит
  значок словом) и без расплывчатости.
- **Перед выпуском:** поднять versionCode, дописать блок строк под новое
  число, добавить его в `NOTES`.

### Доставка файла владельцу

`telegram_send_document` падает с `message caption is too long`, если подпись
длиннее 1024 знаков — подпись короткая, подробности отдельным сообщением.
Транзиентные ошибки транспорта уходят со второй-третьей попытки после паузы
20–40 секунд.

## 5. Проверка до сборки: дымовая компиляция

Локально собрать APK нельзя, но **можно скомпилировать Kotlin-исходники
начисто** — без Gradle, без ресурсов. Это ловит опечатки, необъявленные
имена, отсутствующие импорты и незарегистрированные R-константы до того, как
прогон CI будет потрачен.

Скрипт лежит в рабочем каталоге (`scratch/smoke/compile.sh`), вне
репозитория: он тянет `android.jar` из локального SDK и JVM из
`tools/jdk-arm64` (в `PATH` java нет), а к исходникам подмешивает два файла
заглушек — `RStub.kt` и `BindingStub.kt` (стабы ресурсов и binding-классов
не генерируются).

```
bash scratch/smoke/compile.sh [лог]
```

**Судить по НАБОРУ ошибок, а не по счётчику.** Базовая линия — 121 ошибка
(это шум заглушек, норма). Однажды прогон сошёлся по числу (база была «126»,
и ошибка в неё уложилась), сломанный код уехал в CI, прогон ушёл впустую.
Сравнивать нормализованные списки строк: снять номера строк и пути, отсортировать,
сравнить множества.

Чего смоук не видит по построению:

- `build.gradle.kts` он не читает — **перед пушем обязательно**
  `git grep -n "^<<<<<<< \|^>>>>>>> "` (маркеры конфликта, оставшиеся после
  черри-пика, роняют Gradle в CI);
- разметку (`app:iconGravity`, `app:autoSizeTextType` и прочее) — только сборкой;
- новые строковые ресурсы: если смоук ругается на `xxx_title`, добавить
  `xxx_title` в `RStub.kt` руками (там же `R.attr` и стили темы).

Прогон парсеров на JVM (когда правка в разборе форматов) делается отдельно:
`BookParser.kt` + `Model.kt` + `TextSplit.kt` + заглушка `PdfParser`
компилируются напрямую и гоняются на настоящем файле книги. Регрессия FB2 —
на книге «Пентаграмма войны»: 79 глав, 265 420 слов, 40 сносок по месту, ноль
меток в речи.

## 6. Карта кода

Один модуль `app`, пакет `com.cuber.bookvoice`. Главные файлы:

**Чтение**
- `ReaderEngine.kt` — ядро: книга, позиция, цикл чтения, очередь фраз,
  аудиофокус, медиасессия. Живёт как `internal object` и переживает закрытие
  окна (чтение без окна). Окно общается с ним через интерфейс `ReaderEngine.Host`.
- `MainActivity.kt` — окно читалки: лента, панель, жесты, диалоги.
- `SentenceAdapter.kt` — лента: строки-заголовки глав и строки-абзацы,
  перевод «глава+предложение» ↔ строка (`flatOf`/`placeOf`/`firstInRow`).
- `ParagraphView.kt` — абзац с виртуальными узлами предложений для диктора.
- `SpeechPlayer.kt` — синтез и воспроизведение: очередь заготовок, стык,
  сторожа молчания, обрезка тишины.

**Разбор книг**
- `BookParser.kt` (диспетчер + FB2/TXT/EPUB/zip + DOCX/ODT/HTML),
  `PdfParser.kt`, `Model.kt` (книга/глава/предложение), `TextSplit.kt`
  (разбивка на предложения и абзацы).

**Библиотека и каталог**
- `LibraryActivity.kt` (полка), `BookStore.kt` (реестр книг и мест),
  `BookAdapter.kt`, `BookCovers.kt` (обложки карточек-сетки: достаёт из FB2 и
  EPUB, кэширует на диск и в память, рисует заглушку из названия),
  `CatalogActivity.kt` + `Opds.kt` (сетевые каталоги), `AllFiles.kt`.
  **Страница полки создаётся в конструкторе окна**
  (`LibraryWindowActivity`: `private val library = LibraryActivity(this)`) — то
  есть до того, как у Activity появится базовый контекст. Поэтому в её
  конструкторе нельзя трогать `act` как контекст: поля, которым нужен контекст
  или ресурсы, обязаны быть ленивыми (см. урок 10 в разделе 12).

**Настройки**
- `SettingsActivity.kt` (сборка строк), `SettingsWindowActivity.kt` (окно
  поверх), `SectionActivity.kt` (общая основа окон-разделов),
  `VoicePicker.kt` (единый набор «Голос чтения»), `RateSteps.kt`
  (все значения скорости и тона), `TextScale.kt` (крупный шрифт).

**Синхронизация**
- `SyncStore.kt` (общий файл синхронизации), `YandexDisk.kt` +
  `YandexAuthActivity.kt` (Яндекс.Диск), `BackupStore.kt` (резервные копии).

**Прочее**
- `MediaSessionService.kt` (карточка в шторке, медиакнопки),
  `KeepAwake.kt` (не давать процессору спать), `FaceDownPause.kt` (пауза, когда
  телефон лёг экраном вниз, и продолжение при перевороте вверх), `SilentKeepAlive.kt` (тихий

  кнопки), `Updater.kt` (автообновление), `Diag.kt` (журнал), `Vibra.kt` /

## 7. Читалка «портянка»: устройство и инварианты

### Идея

Раньше лента держала ровно одну главу плюс строку-кнопку «Следующая глава».
Из-за этого из текста нельзя было вернуться на титульную страницу книги —
это была не ошибка прокрутки, а граница списка.

Теперь **вся книга — один список**. Названия глав стали обычными строками
внутри него, смена главы ничего не пересобирает, а только переводит каретку.
Лента собирается один раз на книгу.

Строка ленты — **абзац** (предложения сшиты пробелом), а не предложение.
Предложения внутри абзаца для диктора — виртуальные узлы (`ParagraphView` +
`ExploreByTouchHelper`). Сам абзац как узел не отдаётся, иначе диктор читает
текст дважды.

### Единица места

Место в книге — пара **(глава, предложение)**. Она живёт в трёх местах:

- prefs `"reader"` — «живое» место чтения, пишется часто;
- запись книги в реестре (`BookStore`, поля `chapter`/`sentence`/`readPct`) —
  отсюда полка берёт процент для карточки;
- `rewindFloor` — защита от дрейфа: после одноразового отката назад при
  старте место не записывается ниже этой отметки, пока чтение до неё не дойдёт.

Место обязано доехать до записи книги, а не только до prefs, иначе полка
показывает старый процент. Запись в реестр идёт не чаще раза в секунду с
досылом последнего значения.

### Что чем двигается

По умолчанию место двигает **чтение**, а не рука. Галочка «Прокрутка двигает
место чтения» переключает это на обратное.

Своя программная прокрутка (лента едет за голосом) и рука читателя — разные
вещи, и их различает `scrollRequestRow` / `scrollRequestUntil`
(`SELF_SCROLL_MS = 1500` мс, продлевается из `alignSentence`). Пока заказанная
нами строка не встала наверх, цель руки не записывается.

### Инварианты

1. **«Играет = подсвечено = прочитано диктором».** Единый источник истины —
   позиция в тексте (наш объект в памяти), а не состояние плеера и не DOM.
   Держится на том, что текст — наш объект. **Нарушается переездом на
   веб-движок** — см. раздел 11.
2. **Книга идёт одной лентой.** Не возвращать границу «одна глава = один
   список» — именно она делала возврат к началу книги невозможным.
3. **Место — за прокруткой, а не за рукой.** Верхняя строка ленты становится
   местом только когда лента реально остановилась, и только если сняты три
   заслонки: голос читает / палец на ползунке / прежнее место ещё на экране.
   Палец, ещё держащий ленту, местом не управляет.
4. **Наша прокрутка не должна выглядеть как рука.** Нарушение этого правила —
   откат перехода по главе назад (самый дорогой дефект читалки, разобран
   ниже).
5. **Переход по главе не откатывается.** Кнопки, жесты, оглавление, гарнитура
   ходят через один `goTo(глава, 0)`, который на мгновение ставит чтение на
   паузу. На этой паузе нельзя применять «цель руки» из прошлого места.
6. **Лестница сторожей не обнуляется паузой.** Иначе эскалация «переспрос →
   перезапуск движка → пропуск фразы» недостижима в принципе: на каждом
   «играть» она начиналась бы заново. Снимают её только доспевший синтез и
   перезапуск движка.
7. **Один запрос синтеза в полёте.** Заготовок в очереди три, но живая заявка
   синтеза ровно одна — иначе семантика сторожей едет.
8. **Заготовки не забегают за границу выделенного куска** и за главу таймера сна.
9. **Склейка фраз не переходит границу абзаца** — абзац часто смысловая
   пауза (в дневниках — новая запись).
10. **У ленты должна оставаться метка коллекции.** Если снять её с
    `RecyclerView`, диктор перестаёт прокручивать ленту свайпами и просто
    уводит фокус на нижнюю строку. Проверено дорого: попытка убрать «12 из
    340» вместе с меткой сломала прокрутку, откатывали. Снимать можно только
    счётчик у строки, но не метку контейнера.
11. **У виртуального узла предложения должно быть `isLongClickable = true`** —
    виртуальному узлу никто не выставляет его автоматически, и без него
    «двойной тап с удержанием» не начинает выделение.
12. **Пробросы в `ExploreByTouchHelper` обязательны** — без
    `dispatchHoverEvent`, `dispatchKeyEvent` и `onFocusChanged` узлов
    предложений для диктора просто нет.
13. **Свой сигнал «говори» перед микрофоном не подавать** — распознаватель
    подаёт собственный, вместе звучат как два подряд.

### Самый дорогой дефект читалки (разобран целиком)

Жалоба: «листаю жестами по главам вперёд, а он переходит непонятно как».

Журнал показал: жест работал (главы шли 26 → 27 → 28, начало главы), но
через треть секунды появлялось «переход: глава 25, предложение 20» и тут же
«скачок чтения по прокрутке»; через пять секунд ровно то же место — книга
гуляла между главой 28 и главой 25.

Причина — наш собственный механизм «место за прокруткой». `goTo` на
мгновение ставит чтение на паузу; на этой паузе планировалась отложенная
проверка (через 300 мс), а к тому времени наша же докрутка ленты успевала
записать «цель руки» — верхнюю строку, где лента стояла ДО перехода (читаемое
на новом месте ещё не на экране). Отложенная проверка применяла эту цель и
возвращала место назад. А докрутка к читаемому блокировалась условием
«пока есть цель руки — не двигать», поэтому лента вообще переставала ехать за
чтением. Каждый переход рождал новую цель из прошлого места — замкнутый круг
с неподвижной точкой.

Лечение: своя прокрутка помечается (`markSelfScroll`), цель руки при этом
снимается, отложенная проверка перечитывает состояние чтения внутри лямбды и
не срабатывает, если чтение уже пошло.

**Вывод на будущее:** в этой читалке любой новый механизм, двигающий ленту,
обязан уметь отличить себя от читателя. Это не деталь, а несущая конструкция.

## 8. Слепой пользователь и дикторы

### TalkBack и Jieshuo ведут себя по-разному

Это не оттенок, а разница в диагностике. Собрано по фактам:

| Ситуация | TalkBack | Jieshuo |
|---|---|---|
| Виртуальные узлы без пробросов `ExploreByTouchHelper` | молчит полностью | читает (обходит деревом) |
| Объявление фразы `announceForAccessibility` | читает | читает, но тонет, если совпало со сменой окна |
| Фокус, перенесённый на заголовок при входе в окно | нормально | роняет — имя окна должно жить в заголовке окна |
| Рождение новой медиасессии | объявляет | не объявляет вовсе |
| Обращения диктора к узлу (`ACTION_CLICK`, `ACTION_LONG_CLICK`) | присылает | может не прислать ни разу за сессию |

**Правило ориентации:** «один диктор читает» **не доказывает**, что узлы
подключены правильно. Jieshuo прощает отсутствие пробросов, TalkBack молчит
целиком. Проверять связку «абзац ↔ предложение» надо на TalkBack. Обратно:
если TalkBack молчит на медиакарточке — это ничего не значит, Jieshuo такие
уведомления не озвучивает.

Владелец пользуется Jieshuo; TalkBack вторичен, и тесты на нём дорогие.
Там, где поведение зависит от диктора, решает журнал, а не слух.

### Жест под диктором

При включённом обходе касанием пальцем владеет диктор. Одиночное удержание
пальцем для него — не жест выделения, а «читаю то, что под пальцем».
Собственное удержание владельца — **двойное касание с удержанием**.

Проверено журналом: настоящее касание до текста доходит и при включённом
обходе, поэтому обработчики жестов ставятся **безусловно**, а от задвоения
защищает метка «недавно обработано» (жест и действие диктора на одно
предложение считаются одним поступком).

### Диагностика в журнале

Тег `a11y`: список включённых дикторов, обращения к узлам предложений
(«абзац #N: у диктора предложений M»), пришедшие касания и действия.
Метка «палец» — путь жеста, метка «действие» — путь узла. По ним видно, кто
из двоих не сработал.

**Полезные коды действий:** 16 = `ACTION_CLICK`, 32 = `ACTION_LONG_CLICK`,
16908342 = `ACTION_SHOW_ON_SCREEN` (служебное, диктор подводит узел к экрану).

## 9. Конвейер озвучки

**Заготовки.** Три готовые фразы вперёд. Запас нужен, потому что движок
может замолчать на 12–15 секунд; в запасе 8–15 секунд звука.

**Склейка фраз.** Читаем не по предложению, а куском до ~220 знаков и не
больше четырёх предложений, только внутри главы. 220 — наше число-страховка:
платформенный предел 4000 знаков, но отдельные движки режут ввод на ~512 и
ниже 300. Позиция едет вместе со склеенной фразой. Пауза или прыжок посреди
неё откатывают её целиком — это плата за склейку.

**Обрезка тишины.** Внутри готового файла подрезаются края (порог −40 dBFS,
50 мс в начале, ~83 мс в конце, только 16-битный PCM; принимается и
`WAVE_FORMAT_EXTENSIBLE`). Каждый отказ оставляет в журнале код причины.
Код «тишины по краям нет» — прямой ответ, что пауза в интонации синтезатора,
а не наша.

**Бесшовная передача.** Второй плеер готовится заранее и отдаётся системе
через `setNextMediaPlayer` — звук продолжается тем же трактом. Включена
всегда, кроме режима альтернативной озвучки. Отказы безопасны: не приняли —
стык как раньше.

**Сторожа молчания.** Отдельный надзор на каждый этап (синтез, подготовка
файла, прямая речь) со своими токенами, чтобы событие одного этапа не гасило
надзор другого. Лестница: короткий запал → переспрос → ещё короче → перезапуск
движка → пропуск фразы, чтобы чтение шло дальше. Худший путь — два перезапуска
и пропуск. Сроки (0.4.67, просьба Сергея «давай укорачиваем»): синтез — четверть
времени звучания фразы, 2,5…6 с (было 6 с всегда); переспрос — 1 с; подготовка
своего файла — 5 с (было 12); позиция играющего файла — 4 с (было 6). Перезапуск
движка наступает теперь через 3,5–4,7 с тишины вместо прежних 7 (на самой
медленной скорости потолок в 6 с возвращает прежние 7 с, но там и речь вдвое
длиннее).

**Надзор за нашим плеером** (23.09.2026, просьба владельца: «не понимаю, почему
синтезатор замолкает»). Движок — не единственный, кто может замолчать: бывает,
что файл отдан плееру, а звука нет. Это видно без движка: у играющего локального
файла позиция идёт по времени, поэтому раз в две секунды сверяем
`currentPosition`. Стоит на месте четыре секунды — считаем фразу доигранной и идём
дальше. Так же ловится потерянный `onCompletion` (позиция упирается в
длительность и не растёт) — раньше это было молчанием навсегда: сторож
подготовки снимался, как только файл начал играть, и приглядывать за звуком
дальше было некому. Две предосторожности: судим только после того, как видели
рост позиции (на прошивке, где `currentPosition` всегда ноль, фразы не
обрываются — такой случай попадёт в журнал отдельной строкой), и закрываем
каждую фразу ровно один раз, иначе поздний `onCompletion` от платформы прошёл бы
по уже закрытой фразе и чтение перескочило бы предложение.

**Особый случай — альтернативная озвучка** (фразу целиком играет движок):
там своя ветка сторожа. Раньше срок был одним числом (180 с) — три минуты тишины
на короткой фразе. С 23.09.2026 срок считают. На старт — две секунды: движок
подаёт сигнал «начал говорить» за доли секунды (наши замеры: синтез
13-секундной фразы 0,95 с, проба голоса 0,2…0,4 с), поэтому долгое ожидание
бессмысленно. **Переспроса и перезапуска движка в этом режиме нет** — Сергей
выбрал самую короткую тишину, а они стоили бы ещё четыре секунды; цена выбора:
если движок просто потерял одну заявку, фраза теряется (в обычном режиме её
возвращает переспрос). Вернуть переспрос — правка на пять строк, запись в
docs/TODO.md. После сигнала «начал говорить» срок считают по длине фразы: сколько
ей звучать при текущей скорости, запас 1,4 и четыре секунды сверху, в границах
6…45 с. Оценка темпа (15 знаков в секунду на скорости 1,0) пишется в журнал рядом
со сроком, чтобы её можно было поправить по факту. Надзор по-прежнему только
ограничивает тишину: разбудить замороженный движок он не может — движок
возвращается либо сам на следующую просьбу, либо перезапуском движка (в обычном
режиме это следующая ступень лестницы), либо не возвращается вовсе, и тогда
лечится разрешениями для самого синтезатора. Открытая задача гигиены — второй
детектор: смотреть состояние звуковых дорожек системы (публичный API даёт только
«играет ли что-нибудь», не «кто»), чтобы ловить тишину, не дожидаясь расчётного
срока.

**Очередь фраз в альтернативной озвучке** (23.09.2026, догадка Сергея: «если
синтезатору посылаешь предложение за предложением, может, читает всё без пауз»).
Раньше в этом режиме мы отдавали движку ровно одну фразу и ждали «закончил» — на
стыке слышалась пауза, и каждая фраза стереглась отдельно. Теперь у движка
всегда стоит впереди три фразы: он берёт их подряд, пауз на стыках нет, а срок
сторожа взводится один — у первой фразы очереди (у следующей он начнётся не
сейчас, а после неё, и короткий запал сработал бы вхолостую). Место в книге от
очереди не страдает: каждая фраза отдаётся со своим номером, движок сообщает
«закончил» по каждой отдельно, и закладку читалки по-прежнему двигает то же
событие. Что спрашивать следующим, мы узнаём у читалки тем же `onNeedNext`, каким
в обычном режиме заказываем заготовки, — она сама обрывает список на конце главы,
конце книги и на границе выделенного куска. Прыжок по тексту, повтор предложения
и пауза выбрасывают очередь движка целиком (`flushDirectQueue`): движок при этом
останавливают, иначе он дочитал бы то, что мы уже не считаем своим, и закладка
разъехалась бы со звуком. Ошибка движка по фразе ИЗ ОЧЕРЕДИ закладку не двигает —
читалка попросит эту фразу снова, когда дойдёт до неё; ошибка по звучащей фразе
считается пропуском, как по сторожу.

**Начало чтения без задержки** (24.09.2026, просьба владельца: «чтение
начиналось бы быстрее»). Замер по журналу: между «старт чтения» и звуком
проходит 0,58 с, и это не наш код — заявка уходит движку через 12 мс, играть
файл начинаем через 29 мс после его готовности, а 0,54 с занимает сам синтез
первой фразы (10,6 с речи; движок берёт 40–50 мс на секунду звука). Убрать эту
задержку можно одним способом — приготовить файл до нажатия: окно читалки
открывается на нужном месте за секунды до «читать», и `prewarmCurrent()` просит
у движка ровно ту фразу, с которой чтение начнётся. Место считает `startPlace`
тем же шагом назад, что и откат при старте (msg2093), иначе прогрели бы не ту
фразу. Готовим ОДНУ фразу и только когда не читается; не пригодилась — файл
осиротеет и будет удалён, как любая незапрошенная заготовка. Голос книги и
список голосов движка обязаны быть уже применены: прогрев чужим голосом хуже,
чем никакого (ждём через `whenVoicesReady`, как при смене голоса). Тем же
способом лечится продолжение после паузы: файл звучащей фразы при паузе не
удаляется, `pauseKeepingPhrase` помнит его вместе со скоростью, и «продолжить»
играет тот же файл вместо повторного синтеза — те же полсекунды на фразу.

**Скорость у готовых файлов** (24.09.2026). Скорость применяет движок в момент
синтеза, поэтому готовый файл «помнит» свой темп. Раньше это нигде не
сверялось: после смены скорости до трёх заготовок в очереди и одна
прицепленная доигрывали прежним темпом. Теперь каждый готовый файл помнит
скорость (`Prepared`), смена скорости выбрасывает заготовки (`dropStaleRate`),
а при использовании файла скорость сверяется ещё раз — в очереди, в прицепке и
в только что доспевшем синтезе. Файл не того темпа не играется никогда: он
выбрасывается, и фраза собирается заново. Плата: сразу после смены скорости
следующая фраза собирается без упреждения (доли секунды).

**Конец книги объявляется голосом чтения** (23.09.2026, просьба владельца:
«ждёт секунду и говорит: книга прочитана»). Дочитав до последнего предложения
последней главы с текстом, движок через секунду говорит «Книга прочитана.» — тем
же синтезатором, тем же голосом и скоростью, что читали книгу. Точка в конце стоит
нарочно: без знака конца синтезаторы читают фразу с незавершённой, чуть
вопросительной интонацией (заметил владелец), и знак уходит движку как есть — и в
обычном режиме, и в прямой речи. Говорим именно
нашей озвучкой, а не диктором: чтение живёт и с закрытым окном (`host == null`),
и голос обязан совпадать с чтением. Фраза служебная — места в тексте у неё нет,
поэтому её окончание разбирает отдельный `onPlayerDone`, а не обычный
`onUtteranceDone`; на время фразы движок снова берёт аудиофокус и будильник и
отпускает их, когда она доиграет. Конец книги отличается от «чтение встало» по
месту (`atBookEnd`), а не по факту остановки: сюда же приходят таймер сна «до
конца главы» и конец выделенного куска (#106). Любое действие читателя —
читать, пауза, переход по главе, закрытие читалки — отменяет несказанное и
обрывает звучащее. **Дочитанная книга сразу помечается прочитанной на полке**
(статус и сто процентов в записи книги) — при возврате на полку строка
обновляется сама (`refreshRowsInPlace`), и книга уходит во вкладку
«Прочитанные». Это не отменяет ручной галочки в меню читалки: статус можно
вернуть обратно, и повторное открытие книги его больше не сбрасывает
(`registerOpen` сохраняет «прочитана»).

**Ключ к разбору журнала:** счётчик `s_N` — это номер СИНТЕЗА, не позиция
фразы. Глубина очереди считается с учётом прицепленного и «в полёте» — на
этом счёте однажды и родился дефект с пропадающими кусками текста.

### Прошлые дефекты озвучки (кратко)

- **Пропадали куски текста.** В очередь заготовок попадал файл СОСЕДНЕЙ
  фразы, стык вслепую брал голову очереди, играл чужой кусок, движок через
  полсекунды просил правильный, старый обрывался. Лечение: сверка всего
  списка фраз впереди с тем, что читалка называет следующей; расхождение —
  хвост очереди выбрасывается, голова остаётся.
- **Сверка стыка ломалась после каждого перехода.** В ветке перехода позиция
  читалки ещё не сдвинута, поэтому «следующая фраза» возвращалась та же,
  что уже звучит, и сверка всегда отказывала. Стык откатывался на перезапуск
  — слышимая пауза.
- **Чтение вставало навсегда после паузы.** Пауза гасила заявку синтеза, но
  не снимала метку «заготовка в полёте»; та же фраза видела метку и ждала
  ответа по убитой заявке — вечная тишина.
- **Движок замирал.** Оказалось, система морозит не приложение, а синтезатор.
  Тестеру помогло снятие оптимизации батареи с ДВИЖКА, а не с BookVoice.
  Отсюда продуктовая рекомендация: разрешать работу в фоне нужно синтезатору,
  у него своё имя в списке.
- **Звук пропадал при живом процессе.** Отдельный случай: система уводит
  телефон в сон в щель между фразами (мы играем файл за файлом, между ними
  тишина). Лечится комбинацией `WAKE_LOCK`, экрана «Не засыпать» и тихого
  звукового потока. Развилка «укоротить сторожа или сначала диагностика»
  открыта — решения владельца нет.

## 10. Функции: карта

### Библиотека

- Вкладки-фильтры полки: «Читаю», «Новые», «Прочитанные», «Избранное», «Все».
  «Все» скрыть нельзя. Порядок и набор вкладок настраиваются.
- **Обложки в карточках-сетке** (23.09.2026, просьба владельца: «хочу, чтобы
  показывалось как в FBReader»). Работает только в виде «Сетка»: список
  остаётся строками, число колонок — две, при крупном шрифте одна (см. ниже).
  **С обложкой подписей под картинкой нет** (23.09.2026, решение владельца):
  название и автор и так написаны на обложке — на настоящей как нарисовано, на
  нашей заглушке крупными буквами, — и подпись была бы повтором. Карточка от
  этого короче, книг на экран больше. **Без обложки подписи возвращаются**:
  карточка снова текстовая (название и автор), узнавать книгу больше не по чему.
  **В углу обложки — цифра прочитанного** (только для глаз): единственное, чего
  на обложке нет, поэтому это не повтор, в отличие от подписи. Показывается у
  начатых книг (у никогда не открытых цифры нет — ряд «0%» на полке был бы
  шумом), у дочитанных — 100%, на полупрозрачной плашке, чтобы читалась и на
  светлой обложке, и на пёстрой. Диктору она отдельным элементом НЕ отдаётся:
  процент и так в тексте карточки, лишнего узла и свайпа не появляется. Галочки
  у цифры своей нет — она живёт вместе с обложками. **Полоску прогресса это не
  возвращает** (её владелец запрещал): цифра — не полоска.
  **При крупном шрифте сетка становится в одну колонку** — это слой для
  слабовидящих: им важнее крупная обложка и читаемое название, чем плотность
  полки. Множитель спрашивают у `TextScale`; смена размера пересоздаёт окно,
  поэтому колонки пересчитываются сами. Настоящая картинка достаётся из
  FB2 (потоково, из `<binary>`, по ссылке в `<coverpage>`), из EPUB (по описи:
  свойство `cover-image`, старая ссылка `<meta name="cover">`, а если обложка —
  отдельная страница XHTML, то из её `<img>`), из книги внутри архива (архив
  определяется по СОДЕРЖИМОМУ — первые байты `PK`, как в `BookParser.isZip`, а не
  по расширению: книги приходят архивом под именем `.fb2` — владелец прислал
  такую, «Карточные игры России»; в архиве
  сначала ищется FB2, потом EPUB — тот же порядок предпочтения, что у разбора
  книги в `BookParser.parseZip`, поэтому обложка принадлежит той книге, которая
  откроется; вложенный архив, zip в zip, не разбирается — там будет нарисованная
  заглушка) и из **PDF** (23.09.2026): в PDF картинки-обложки нет, поэтому первая
  страница отрисовывается. Рисует **системный отрисовщик Android**
  (`android.graphics.pdf.PdfRenderer`, внутри PDFium): он нативный, быстрый и
  понимает то, чего нет у `pdfbox-android`, — в первую очередь JPEG 2000. Так и
  нашлась ошибка первой версии: у присланного владельцем «Человека и мира»
  (5 класс) обложка — картинка в JPEG 2000, pdfbox отдавал вместо неё пустой лист,
  и книга получала нарисованную заглушку. `pdfbox` остался **запасным путём**: он
  открывает файл потоком и снимает пустой пароль там, где системный отрисовщик
  откажет. Картинка берётся сразу в размер карточки (страница в точках, 1/72
  дюйма) и сохраняется JPEG-ом, дальше путь общий (кэш, проверка размера
  оригинала, декодирование). Обложкой не считается только **ровный светлый лист
  без «чернил»** (≥99,85% точек — фон, и сам фон светлый, яркость ≥0,85): так
  выглядит пустая страница. Первая версия правила (97% фона) считала пустым
  титульный лист текстового PDF — а это как раз книги владельца, — и настоящая
  первая страница подменялась заглушкой; порог поднят именно поэтому. Однотонная
  ТЁМНАЯ обложка под правило не попадает и показывается. Доля фона и «чернил»
  пишется в журнал, чтобы порог можно было поправить по факту. FBReader на тех же
  книгах показывает первую страницу так же.
  У TXT, DOCX и ODT обложки нет
  вовсе — вместо серой дыры рисуется обложка из названия (цветной фон, название
  словами), поэтому высота карточки у всех книг одинаковая. Готовые байты
  лежат в `filesDir/covers`, декодированный битмап — в памяти; достаётся всё в
  фоне одной ниткой и только для видимых карточек — скан полки обложек не
  добывает нарочно, иначе открытие полки распаковывало бы все книги подряд.
  Кэш обложек входит в **общую строку «Кэш»** в настройках: владелец просил
  оставить одну настройку, как было, поэтому и размер, и очистка у обложек общие
  с разобранным текстом (`BookCache.usedBytes`/`clearAll`). Подрезка — по объёму
  (32 МБ) и по числу файлов (300), первыми уходят давно не использованные.
  Рядом с картинкой хранится размер файла книги на момент доставания: книгу
  заменили по тому же адресу — кэш снимается и обложка берётся заново (тот же
  приём, что в `BookCache.signature`). Книгу удаляют с полки — обложка уходит
  вместе с разобранным текстом (`BookCache.remove`), сирот не остаётся.
  **Для диктора обложка не существует:** в разметке она помечена как
  неважная, узел карточки по-прежнему один, текст тот же — название, автор,
  процент. Это условие владельца, нарушать его нельзя: лишний узел в обходе
  означает лишний свайп на каждой книге.
- Обложки **включаются и выключаются галочкой** «Показывать обложки книг» в
  настройках, раздел «Библиотека и скачанные» (по умолчанию включены). Галочка
  снята — карточка снова только текст, и книгу ради картинки мы не открываем
  вовсе. Полка перечитывает галочку в `resume()`, то есть возврат из настроек
  применяет её сразу; окно полки живёт всё время, пока живёт окно-дом.
- Пункт «Удалить всё из „вкладка“» живёт в меню «⋮» и чистит ОТКРЫТУЮ вкладку.
  С 22.09.2026 он есть и на «Все» (там чистится вся полка) — раньше его на этой
  вкладке намеренно не показывали. На «Избранном» он снимает метку, книги
  остаются. Без галочки «Удалить и файлы» книги уходят с полки и прячутся от
  скана, поэтому сами на полку не возвращаются.

### Форматы

Читаются: **FB2** (и `.xml`), **TXT** (в разных кодировках), **EPUB**,
**PDF** (текстовый слой; скан — честное «не читается»), **zip** с книгой
внутри, **DOCX**, **ODT**, **HTML**.

Скачиваются, но помечены «не читается»: **MOBI, RTF, DOC, PDF в RAR**.
Пометка стоит прямо в подписи формата — для незрячего это
единственный способ узнать это до скачивания.

**Каталог отдаёт часть книг архивом** (24.09.2026, вопрос Сергея: «говорит,
что скачивает FB2, а скачивает в zip»). Живая проверка OPDS: fb2, txt, html и
rtf flibusta помечает «+zip» (`application/fb2+zip`, `txt+zip`, `html+zip`,
`rtf+zip`) и отдаёт `application/zip` — файл у сервера называется
«Название.fb2.zip»; epub приходит как `epub+zip` (zip и есть его формат), а
mobi, pdf и djvu — готовыми файлами (mobi сервер ещё и собирает на лету). Мы
писали упакованное под книжным расширением: `.fb2`, внутри которого архив.
Внутри читалки это не мешало — архив определяется по содержимому
(`BookParser.isZip`), а не по расширению, — но в папке и на Диске файл врал о
себе, и любая другая программа видела архив. Теперь при скачивании архив
разворачивается (`BookParser.unpackBookFile`), и сохраняется сам файл книги под
своим расширением; epub, docx и odt не трогаем (zip — их собственный формат), а
если книги внутри нет или запись больше потолка — файл остаётся архивом, но с
честным `.zip`. Картинки из упаковки (у txt и html рядом с книгой лежат обложка
и иллюстрации) не сохраняем: текст книги целиком в самом файле, а картинки мы
не показываем. Старые книги, скачанные прежним способом, остаются как есть:
имя у них прежнее, но открываются они, читаются и обложки к ним достаются по
содержимому — ровно как и раньше.

**Служебный файл описания внутри архива** (24.09.2026, архив «Жизнь в поместье»
от Сергея). В упаковке бывает ДВА файла: сама книга и служебный `.fbd` — это
тоже FB2, но из одной `<description>`: название, автор, аннотация, ни одной
главы. Идёт он первой записью, и разбор архива, берущий первую разобравшуюся
запись, принимал его за книгу — книга открывалась пустой. Теперь `.fbd` книгой
не считается нигде: при разборе архива он пропускается, а отдельным файлом
честно отвечает «не читается». Тем же выпуском в список того, что достаётся из
архива, добавлен `.pdf`: у книг без FB2 flibusta кладёт в архив PDF и описание,
и теперь сохраняется настоящий `.pdf` (проверено на архиве Сергея: 12,5 МБ PDF
плюс 17 КБ описания → на диске один `.pdf`).

Особенности FB2:
- сноски читаются **по месту** (штатный механизм FB2), а не главой в конце:
  концевые примечания на слух не доходят. Перед текстом сноски звучит слово
  «Сноска.» — сигнал, что это ремарка, а не рассказ;
- `<text-author>` — подписи под цитатами — читаются (однажды пропадали);
- имя главы берётся только из заголовка на верхнем уровне секции, иначе
  заголовок стиха перебивал название главы;
- прозрачная секция-обёртка отдаёт своё название первой вложенной главе;
- аннотация книги читается первой главой;
- неназванные главы короче 30 слов до первой названной выбрасываются как
  титул/копирайт.

### Голос

- Выбор состоит из трёх строк-значений: **Движок / Язык / Голос**. Список
  голосов показывает только выбранный язык. Настоящие выпадающие списки
  отвергнуты — у них прыгающий фокус диктора; используется кнопка со
  значением и список одиночного выбора.
- Выбор голоса помнится **на каждый движок отдельно** — иначе строка «Голос»
  показывает голос предыдущего движка.
- Названия языков — из своей таблицы: системный ICU на прошивках врёт.
- Скорость: 0,5…6,0 ровным шагом 0,1. Тон: 0,5…2,0. Все значения живут в
  одном файле (`RateSteps.kt`) — это единственный источник для всех ползунков
  и кнопок.
- Если выше 2–3 скорость «не меняется» — режет движок, а не ползунок.
  Проверять на разных движках; измерить можно по размеру синтезированных
  файлов в журнале (калибровка: 48 000 байт/с).
- Единый набор «Голос чтения» — один код на панель читалки и на Настройки:
  порядок, подписи и содержимое списков совпадают. Первая строка — «Читать/
  Пауза», когда книга открыта, и «Прослушать» (образец голоса), когда нет.
- Список голосов после выбора НЕ закрывается (22.09.2026): голос применяется
  сразу и тут же звучит образцом фразы — так голоса перебираются на слух.
  Закрывает список сам читатель, кнопкой «Закрыть». В читалке с открытой книгой
  образца нет: там выбор голоса перечитывает текущее предложение (msg5604).

### Сетевые библиотеки (OPDS)

- Каталоги по URL, просмотр как библиотека, скачивание офлайн.
- В стартовом наборе три живых каталога (22.09.2026): `flibusta.is/opds`,
  `n.flibusta.is/opds` и `coollib.net/opds`. Набор докладывается сам при
  открытии окна «Каталоги» — руками адреса набирать не нужно. Мёртвые зеркала
  из набора вычищаются (msg1776): так ушло `flibusta.site/opds`.
- «Авторизация» во внешнем каталоге — это раздел **самого сервера**, форма
  входа на сайте; приложение её показать не может. Механика входа разобрана
  (HTTP Basic), но работа отложена.
- **Сортировок OPDS не отдаёт.** Каталог отдаёт только недельный срез
  новинок по жанру, и он доступен в приложении в пять касаний. Тема закрыта,
  повторно не предлагать.

### Синхронизация между устройствами

- Файл в облачной папке переносит **места чтения, закладки, цитаты,
  избранное**. Книги — отдельной галочкой и только по кнопке.
- Файл — **объединение**, а не «наше состояние»: чужое не стирается, даже
  если этой книги у нас нет.
- Книги сопоставляются **по имени файла** (пути на разных устройствах
  разные) — две разные книги с одинаковым именем сольются.
- Удаление передаётся **меткой**, а не отсутствием книги: полка второго
  устройства может быть не просканирована, и пустота стёрла бы всё.
- Вход в Яндекс.Диск сделан (PKCE без секрета). Вход через Google-аккаунт
  отложен: это OAuth-ключ приложения, привязанный к подписи, плюс работа под
  аккаунтом владельца.
- Автозабора книг нет и не планируется — только кнопкой.

### Настройки

Разделы: «Экран книги», «Чтение», «Голос», «Библиотека и скачанные»,
«Разное». Строка-значение и кнопка-действие различаются на слух: значение
объявляется обычным текстом, действие — кнопкой.

Прерывания чтения извне живут в «Чтении» и оба галочками: «Останавливать
чтение, когда наушники отключаются» (включена по умолчанию) и «Останавливать
чтение при включении экрана» (снята по умолчанию). Вторая ловит и разблокировку
— при снятии замка на горящем экране отдельного SCREEN_ON может не прийти; за
это она встаёт на паузу и от вспышки на уведомление, и это решение владельца
(22.09.2026). Механика — в `ScreenOnPause.kt`, живёт ровно пока идёт чтение.

Третья галочка — «Останавливать чтение, когда телефон перевёрнут экраном вниз»
(23.09.2026, снята по умолчанию). Экран погашен и телефон лёг экраном вниз —
чтение встаёт на паузу; перевернули экраном вверх — продолжается само. Механика
— в `FaceDownPause.kt` (акселерометр, те же пороги, что у жеста таймера), и
живёт она тоже ровно пока идёт чтение. **С таймером сна они не пересекаются:**
пока открыто окно ожидания жеста (`ReaderEngine.sleepWaiting`), переворот
принадлежит таймеру — им продлевают чтение, и сторож переворота в эти секунды
молчит. Пауза «по перевороту» — временная, как звонок: таймер сна она НЕ снимает
и продолжается сама, а пауза человека (кнопкой, гарнитурой) переворотом не
снимается никогда.

Крупный шрифт (слой для слабовидящих): множитель поверх системного, высокая
контрастность через атрибуты темы, «простой экран» (убирает лишние кнопки,
но «⋮» не убирается никогда — через него достаётся всё).

## 11. Что отложено и что запрещено

**Не предлагать заново** (решение владельца, повторный заход — нарушение):

- **Полку не трогать — кроме обложек в сетке.** Ни потолки строк в карточках,
  ни колонки по ширине, ни полоску прогресса. Тема закрыта владельцем, история
  правок откачена. Единственное, что владелец разрешил сам (23.09.2026, «как в
  FBReader»), — картинка обложки в карточке-сетке; список при этом остаётся
  строками, колонок по-прежнему две, полоска прогресса запрещена.
- **Кнопку питания не предлагать.** С Android 9 приложению её не доставляют.
- **Веб-движок (WebView) не предлагать.** HTML не знает предложений, а
  навигация по предложениям — суть читалки; инвариант «играет = подсвечено =
  прочитано» держится на том, что текст — наш объект в памяти, а не DOM.
  Пересмотреть только при появлении EPUB как основной задачи или PDF с
  фиксированной вёрсткой.
- **Свою разметку уведомления не делать.** Диктор прочитает её как обычное
  уведомление, каждую кнопку придётся подписывать руками на каждой прошивке.
- **Не дробить строку карточки по предложениям** — диктор объявляет
  обновления карточки, которая у него в фокусе; слушать это невозможно.
- **Медиакарточку не прятать и плеер не убирать** — потеряются медиакнопки
  гарнитуры и «волшебное касание».
- **Сортировки жанра в каталоге не предлагать** — каталог отдаёт только
  недельный срез новинок, он уже доступен в пять касаний.
- **Шкалу таймера сна 15 минут не вводить** (но это не запрет на правки
  таймера вообще).
- **«Моталку» не переименовывать** — слово владельца, ему оно нравится.
- **Скрытые галочки не прятать.** Недоступная настройка гасится с
  произносимой причиной: спрятанная галочка для незрячего = пропавшая.

**Отложено (не начинать без просьбы):**

- Картинки FB2 и типографика (красная строка, поля, колонтитул).
- RTF (глав в разметке нет — выйдет одной главой, как TXT), FB3, MOBI/AZW3,
  DJVU/CBZ, старый бинарный `.doc`, rar-архивы.
- Авторизация и «Моя полка» во внешнем каталоге.
- Вход через Google-аккаунт.

**Никогда не делать в этом проекте:**

- Не писать платформенные API по памяти (см. раздел 3).
- Не выдавать меру за причину (см. раздел 3).
- Логин и пароль владельца — не в чат.

## 12. Уроки, стоившие прогонов

1. **Сборка до пуша** — workflow собирает голову ветки на remote, а не
   локальный коммит. Три истории: закоммитили 0.4.2, запустили без пуша —
   собрали 0.4.1.
2. **Смоук по счётчику** — ошибка уложилась в «нормальное» число, сломанная
   сборка уехала в CI. Сравнивать наборы строк.
3. **Маркеры конфликта** — после черри-пика в `build.gradle.kts` осталась
   служебная строка `<<<<<<< HEAD`; смоук не читает gradle-файлы, поймал бы
   только CI. Перед пушем — `git grep` по маркерам.
4. **API по памяти** — метода не существовало в SDK; каждая такая ошибка
   стоила прогона и правки поверх уже выпущенного релиза.
5. **Самодельный парсер подписи** — выдавал разные отпечатки на одинаково
   подписанных APK, то есть молча врал.
6. **Метка времени в журнале** — «дыра» во времени между отметками означает
   заморозку процесса, а не баг кода. Различать «спал синтезатор» и «спали мы».
7. **Локальная сборка** — невозможна принципиально, не тратить на неё время.
8. **Имена интерфейса** — проверять на слух.
9. **Отложенная проверка с задержкой** — всегда перечитывать состояние внутри
   лямбды: за 300 мс мир успевает измениться (см. раздел 7).
10. **В конструкторе страницы-«дома» нет контекста.** `LibraryWindowActivity`
    создаёт страницу полем: `private val library = LibraryActivity(this)`, а
    значит её конструктор работает ещё ДО `attachBaseContext`. Любое обращение
    к `act.applicationContext`, `act.resources` или `act.getSharedPreferences`
    прямо в поле — `NullPointerException`, и приложение не запускается совсем
    («Unable to instantiate activity»). Так ушла в народ сборка 0.4.57: поле
    обложек читало `act.applicationContext`, стек
    `LibraryActivity.<init>(LibraryActivity.kt:115) ← LibraryWindowActivity.<init>`.
    Правило: поля страницы, которым нужен контекст, создаются **лениво**
    (`by lazy`) и только внутри методов, которые зовутся после `onCreate`.
    Собрано и проверено локально — этого мало: падение видно лишь на устройстве.
