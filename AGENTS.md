# BookVoice

Читалка книг для незрячих пользователей, управление голосом TalkBack. Kotlin без
Compose: обычные Activity, XML-разметка, viewBinding.

## ПАКЕТНОЕ СКАЧИВАНИЕ: «ВСЯ СЕРИЯ / ВЕСЬ АВТОР» ИЗ КАТАЛОГА (20.11.2026, собрано из кода, не испытано)

  отдельную папку. Потолок-переспрос НЕ нужен («пусть просто качает и скажет,
  сколько книг»; «на 500 не бывает» — значит и пугать числом нечего).
- Вход: долгое на строке «Все книги автора…» / «Все книги серии…» ВНИЗУ

  переход. 23.11.2026 (просьба Сержа: «при долгом нажатии на серию была менюшка
  и в ней скачать всю серию или всего автора»): долгое открывает МЕНЮ

  автора» — что есть у книги), а не стартует сразу; пункт сам знает состояние:
  пачка этой ленты качается → «Отменить качание этого списка», ждёт в очереди
  → «Убрать этот список из очереди». Вторая отмена — кнопка в шторке (общая
  ACTION_CANCEL, снимает ТОЛЬКО текущую пачку, очередь остаётся).
- ОЧЕРЕДЬ ПАЧЕК (23.11.2026, просьба Сержа: «несколько серий подряд набавлял,
  и оно добавлялось в очередь все»): `DownloadService` держит очередь пачек
  (`enqueueBatch`/`beginBatch`/`nextBatch`/`jobEnded`): долгое во время чужой
  пачки НЕ отменяет и НЕ говорит «занято» — пачка встаёт в конец, окно
  докладывает «В очереди: качается ещё N списков перед этим»; по конце текущей
  следующая стартует САМА (журнал «собираю список …» уже без нового касания —
  23.11 на эмуляторе поймано живьём). ТОТ ЖЕ адрес ленты дважды не встанет

  долгое по той же строке → пункт «Убрать этот список из очередь»

  работы — «подожди текущую загрузку» (окно и служба оба). Очередь живёт

- ДРУГИЕ КАТАЛОГИ (22.11.2026, вопрос Сержа «только для флибусты или нет»):
  пачка по строке каталога — общий OPDS, проверено на Coollib живьём: долгое на

  быстрый). Что флибусто-специфично и как обходится:
  (1) Coollib НЕ ОТДАЁТ часть книг (самиздат/компиляции с <rights>
  «Заблокировано!»): записи без acquisition парсер раньше молча делал папками —
  теперь по <rights> это Книга без форматов: страница говорит «нет форматов»,
  пачка считает их и докладывает «Без файла в списке ещё N — каталог их не
  отдаёт» (и в стартовом тосте), а если годных ноль — «каталог не отдаёт ни
  одной книги». Права на файлы — не наша воля, качаем что отдают.
  (2) Вход для ЛЮБОГО каталога добавлен: «⋮» на странице со списком книг →
  «Скачать весь этот список» (batchToggle адреса ленты, kind series). Когда
  каталог не даёт строк «Все книги серии/автора» (у Coollib часть книг вообще
  без них, у флибусты [litres]-сборники) — человек уже внутри списка, пачка
  берёт его. В меню нет: корень, каталоги, разделы без книг, страница книги.
  (3) Смешанная лента (папки-узлы вперемешку с книгами — Coollib автор) — тоже
  узел: спуск в «по алфавиту» сразу, книги узла не в счёт; у Coollib подлент
  нет (500) — тогда честно обходим страницы и докладываем про блокировки.
  (4) Имена: заголовок ленты Coollib приходит с разметкой («Книги автора
  \n Thanaton») — entryTitle() схлопывает пробелы у ИСТОЧНИКА (список,
  страница, папка пачки слышат одно чистое имя); имена-расписания
  («Новинки с 15.11.2026 по 22.11.2026») для папок НЕГОДНЫ — stripDateTitle
  режет даты: папка «Новинки» не меняется на следующий день. Год в имени
  книги («Фантастика 2024-176», «Июнь 1941») — не расписание, не резать.

## ПАПКИ ДЛЯ СКАНИРОВАНИЯ: ПОЛКА СМОТРИТ В НЕСКОЛЬКО МЕСТ (20.11.2026, собрано из кода, не испытано)

- Слова Сержа: «чтобы книги искались в двух-трёх папках… я имел в виду папки
  для сканирования». Аналог `FoldersToScanActivity` из @Voice, но проще.
- Сделано: в «Настройках» под «Папкой книг» строка «Папки для сканирования»
  (`ScanFolders.kt`, prefs `scan_folders` — множество ПУТЕЙ НА ДИСКЕ). Диалог:
  первой строкой «Добавить папку…», дальше сами папки; касание папки —
  переспрос и убрать (книги её ОСТАЮТСЯ на полке, скан просто перестаёт туда
  заглядывать — сказано и в диалоге, и в отчёте). СТЕРЕТЬ папку с диска там
  НЕТ и не добавлять без просьбы (Серж подтвердил 20.11.2026: «так и
  оставляем»): удаление файлов не туда, где их выбирают.
- Сканирование — напрямую файлами, ЗНАЧИТ НУЖЕН «Доступ ко всем файлам»: без
  него строка показывает «нужен доступ», а «Добавить» ведёт включать. Главная
  папка этим не ограничена (у неё SAF-дорога), не путать.
- Общий механизм НЕ дублирован: `scanByFiles` обобщён в
  `scanFilesUnder(root, label, avoidPaths)` — та же глубина `MAX_SCAN_DEPTH`,
  те же `supportedFileName`, та же метка «не возвращать при скане», тот же
  итог в одном тосте (`ScanReport` складывается). `avoidPaths` — один проход
  по реестру в начале: доп. папка внутри папки книг не заводит файл вторым

## ОДИН ОТКАЗ ДВИЖКА — НЕ ПРИГОВОР; СЕТЕВОЙ ГОЛОС НЕ ПОДСТАВЛЯЕМ (19.11.2026, правка без сборки)

## ВКЛАДКИ ПОЛКИ: ПРОСТОЙ `View` ПОД AT_MOST СЪЕДАЕТ ВСЮ ШИРИНУ (03.11.2026, правка без сборки)

- Жалоба Сержа: «в библиотеке две вкладки, свайпом переключаюсь на „Все“, синтезатор
  говорит, что переключил, а вверху визуально вкладка не поменялась — как была, так
  и осталась». ПРОВЕРЕНО НА ТЕЛЕФОНЕ снятием иерархии видов
  (`adb shell dumpsys activity com.cuber.bookvoice`, раздел `View Hierarchy`):
  в ряду `filterBar` было ДВЕ вкладки, но первая занимала 1198 px (вся ширина экрана),
  вторая шириной 252 px стояла РОВНО за правым краем. То есть выбранная вкладка была
  за экраном: отсюда «озвучка есть, а наверху ничего не меняется».
- ПРИЧИНА: `HorizontalScrollView` в `activity_library.xml` имел
  `android:fillViewport="true"`. Он растягивает ряд до ширины экрана, и подписи
  достаётся ограничение AT_MOST на всю ширину. Полоска-индикатор под вкладкой —
  обычный `View` с `MATCH_PARENT`; у простого View своей ширины нет, и под AT_MOST он
  отдаёт РОВНО предложенный размер (`View.getDefaultSize`), колонка вкладки
  раздувается, а следующие вкладки уезжают за край.
- ПРАВИЛО: в контейнере, куда подставляются `MATCH_PARENT`-дети, НЕ ставить
  `fillViewport`. Простой `View` (полоска, разделитель) внутри `wrap_content`-колонки
  нельзя оставлять `MATCH_PARENT`, если по ширине колонку никто не ограничивает
  явно. Сейчас `fillViewport` из разметки убран — не возвращать.
- ВТОРАЯ ОШИБКА ТАМ ЖЕ: `scrollSelectedTabIntoView` брал `left/right` у ПОДПИСИ, а она
  лежит внутри колонки и её `left` всегда 0. Из-за этого координаты сравнивались с
  `scrollX` ряда неправильно, и прокрученный ряд откручивался в начало вместо того,
  чтобы показать выбранную вкладку. Теперь координаты берутся у колонки
  (`label.parent`).
- Как проверять без сборки: `adb shell dumpsys activity com.cuber.bookvoice` печатает
  строки вида `android.widget.LinearLayout{… 0,0-1450,182 #7f0800ed app:id/filterBar}`
  и ниже размеры каждой вкладки — по ним сразу видно, растянута ли первая вкладка.
  `uiautomator dump` этого НЕ покажет: вкладки за краем в дерево доступности не
  попадают (из-за этого казалось, что вкладка одна).

## СПИСОК ГОЛОСОВ ДВИЖКА ПЕРЕЧИТЫВАЕМ ПРИ ЗАХОДЕ (30.10.2026, правка без сборки)

- Жалоба Сержа: «в TeraTTS голоса добавляются из вав-файлов, я сделал третий голос, а
  в читалке в списке остаются два — надо перевыбирать движок». Причина: `SpeechPlayer.voiceCache` —
  СНИМОК, сделанный при запуске движка; `VoicePicker.refresh()` повторял запрос ТОЛЬКО
  когда снимок был ПУСТ, и добавленный движку голос мы не видели. Перевыбор движка
  помогал потому, что `SpeechPlayer.start` поднимает движок заново.
- Теперь (`VoicePicker.kt`): `askVoices(p){…}` — единственный вход за свежим списком
  (засечка `voicesAskedAtMs`, `askingVoices`, запрос в стороне через
  `SpeechPlayer.refreshVoices`; дольше `VOICES_SLOW_MS` 700 мс — вслух «читаю список
  голосов…», разницу числа голосов пишем в журнал). `refresh()` спрашивает и когда
  снимок старше `VOICES_FRESH_MS` (5 с), `resetLang()` (зовётся при открытии панели)
  сбрасывает засечку, а перед списками языков и голосов стоит `refreshThen { … }`.
- ПРАВИЛО: любой список от движка — это снимок. Всё, что меняется в САМОМ движке
  (голоса, языки), читаем перед показом, а не по событию «список был пуст».
- Ограничение: если движок отдаёт клиентам устаревший список (кэширует у себя),
  перечитка не спасёт — понадобится пересоздать соединение `TextToSpeech`, а это
  обрывает звук. Сначала смотреть журнал: строка «список голосов движка обновлён»
  должна появляться после добавления голоса.

## Смена голоса и движка: окно прогрева (05.10.2026, сборка 236)
- Что это. После смены голоса или движка даём движку «окно прогрева»: пока оно
  идёт, сторож синтеза только ждёт — ни переспроса фразы, ни перезапуска движка
  (прежде он это делал через 2,5 с и тем губил загрузку нового голоса: в журнале
  30.09 смена голоса стоила 13-18 с тишины). Окно закрывается само, как только
  придёт первая фраза нового голоса. Срок: 6 с локальному голосу, 12 с сетевому
  и помеченному медленным (`SLOW_TIMING.warmupMs` в таблице `Timing`) — решение
  Сержа 05.10.2026 после вопроса «а локальные синтезаторы мы так не сломаем?».
- Где в коде (`SpeechPlayer.kt`): `armVoiceWarmup` / `warmingVoice` /
  `warmLeftMs` / `voiceWarmFuseMs`, поле `voiceWarmUntilMs`; вызовы — из
  `selectVoice` (когда голос правда сменился) и из `setEngine`; первая ветка
  `synthFuseFor` и ветка в начале `onSynthWatchdog`. Рядом три независимых
  куска той же сборки: в `dropPrepared` при смене голоса в файловом пути гасим
  очередь движка (`tts.stop`) и САМИ закрываем старые заявки; `forgetSlowMark`
  снимает пометку «медленный», если голос ответил сразу после смены; в
  `synthFinished` (ветка «фразу ждало чтение, пришла файлом») зовём
  `requestPrefetch()` и `exoTopUp()`, иначе конвейер просыпался только на «фраза
  доиграла» и первая пауза после смены выходила в 1,2-2,7 с.

## ПОРЯДОК ЧТЕНИЯ: ЕДИНИЦЫ РЕЧИ (08.10.2026)
- Жалоба «два раза какая-то фраза повторялась» (журнал 21:43 и 12:45). Причина: у
  фразы, разрезанной на куски (слова автора и реплика, «голова и хвост» после
  перехода), ВСЕ куски шли с ОДНОЙ позицией — опознать их было нечем. Хвост фразы
  вставал в список плеера ПОСЛЕ следующего предложения (оно уже стояло
  заготовкой), а чтение, услышав «доиграла» от чужого файла, двигало место и
  просило прозвучавшее заново; кэш сыгранных отдавал звук мгновенно. Разбор обоих
  случаев — `docs/HISTORY.md`, «Порядок чтения: единицы речи».
- ВАЛЮТА ТЕПЕРЬ ОДНА — ЕДИНИЦА РЕЧИ: ключ = позиция в книге + номер куска
  (`Units.key`, файл `Units.kt`; формула живёт ТОЛЬКО там). Ключ — опознание
  везде: очередь заготовок, список плеера, кэш сыгранных, отчёт «доиграла».
  ТЕКСТ ОПОЗНАНИЕМ БЫТЬ НЕ МОЖЕТ — в книге полно одинаковых фраз.
- Три правила, каждое закрывает свой класс жалоб: (1) список плеера наполняется
  ТОЛЬКО по порядку ключей — заготовка не своей очереди ждёт в `readyQueue`
  (`exoAppend(automatic = true)` → `HELD`), и ждём лишь то, что есть в
  конвейере (`unitInPipeline`), иначе встали бы в тишину; (2) единица,
  прозвучавшая в этом проходе, вперёд второй раз не звучит (`playedKeys`), повтор
  — только по просьбе человека (`speak(..., userAsked = true)` → играем из кэша
  сыгранных); (3) указатель чтения двигается только по СВОЕЙ единице
  (`SpeechPlayer.lastDonePos/lastDoneLast` против `fragmentPos`), а если звук

## PDF: ГЕОМЕТРИЯ, РАЗРЯДКА, КОЛОНТИТУЛЫ (09.10.2026)
- Жалоба Сержа: PDF читается рывками — «качествен- ное», а колонтитул «Ч ас ть I.»
  синтезатор читает по буквам. Разбор и замеры — `docs/HISTORY.md`.
- `PdfParser` чистит по правилам: (1) перенос на стыке строк и страниц — дефис
  приклеен к букве, дальше строчная → убираем дефис и пробел (перед цифрой или
  заглавной оставляем: «1-й»); (2) невидимые знаки (мягкий перенос, «¬», нулевые
  пробелы) снимаем сразу; (3) колонтитул и номер страницы — строка на краю, та же
  на `max(3, n/100)` страницах; (4) слово, разрезанное границей страниц, дошиваем
  при строчной; (5) мусорное название из метаданных отбрасываем — берётся имя
  файла. ПОРОГ НЕ СНИЖАТЬ (при «≥2» учебник истории терял «В VII в. до н. э.»),
  разряженное БЕЗ повтора не трогать.
- ГЕОМЕТРИЯ — по образцу @Voice (их строка «минимальное расстояние между
  символами»): разрядку склеиваем по ЗАЗОРАМ между знаками: медиана зазора мала —
  обычный текст, не трогаем; заметная — склеиваем, пробел оставляем только там,
  где зазор шире 1,5 медианы. Откат, если пробелов не убавилось или вышло слово
  длиннее 30 знаков. КОЛОНКИ: PDFTextStripper склеивает строки левой и правой
  колонки в одну (общая высота) — такую строку РЕЖЕМ по полосе пустого места,
  затем левая колонка целиком, потом правая; нет полосы — порядок не трогаем.
- ГАЛОЧКИ (просьба Сержа «чтобы можно было вернуть»): `expert_pdf_headers`,
  `expert_pdf_spacing`, `expert_pdf_columns` в опытных настройках, по умолчанию
  включены. Набор чисток — `PdfParser.Options` (ставит `BookVoiceApp`, меняет
  `SettingsActivity.pdfCleanChanged`), кэш сверяет отпечаток (`BookCache.Entry.stamp`).
- Кэш разбора `BVA` (`BVB` — следующая смена). 263x: у PDF БЕЗ закладок главы ищутся
  по КЕГЛЮ (`HEAD_SIZE_RATIO` 1,35), галочка «Искать главы по размеру шрифта»;
  меньше трёх заголовков — делим по страницам. ПРОЦЕНТЫ СКАЧИВАНИЯ ВСЛУХ НЕ ЧИТАЕМ:
  у кнопки подпись без числа, число — в строке, скрытой от диктора (`dlProgressRow`).

  («в PDF нет извлекаемого текста»). На этом сломалась сборка 253g.

## Конец книги: «удалить или оставить» (07.10.2026)
- Книга дочитана — спрашиваем, удалять ли её вместе с файлом. Вопрос задаём ПОСЛЕ
  фразы «книга прочитана» (`ReaderEngine.finishEndAnnounce` → `askDeleteAtEnd`),
  окно — `MainActivity.maybeShowEndAsk` («Удалить „…“ вместе с файлом?», кнопки
  «Удалить» и «Оставить»). Иначе диктор и голос чтения говорят разом.
- Экран погашен — вопрос ЖДЁТ (адрес держит движок, `endAskUri`), окно спрашивает
  при возврате (`onWindowFocusChanged`). Другая книга или «читать»/«пауза» —
  вопрос снимается.
- Галочка «Спрашивать про удаление дочитанной книги» — Настройки → «Библиотека»,
  первая строка (`ReaderEngine.KEY_ASK_DELETE_END`, по умолчанию включена).
  Читается на каждом конце книги, применяется сразу.
- Удаление — общее ядро `BookDelete.kt` (вынесено из `LibraryActivity`): файл,
  запись, кэш, метка синхронизации, скрытие от скана. Второй копии быть не должно.
- ПРАВИЛО (12.10.2026, решение Сержа: «если книга не удаляется — пускай она будет
  на полке; я лучше в проводник зайду, удалю её, потом полка скажет, что книги
  нету, и запись удалит сама»). `BookDelete.book` СНАЧАЛА пробует стереть файл и
  возвращает `Outcome(removed, fileGone)`: файл в папке книг стереть не вышло —
  книгу НЕ трогаем вовсе (ни записи, ни метки), она остаётся на полке, а сказанное
  вслух берётся из `book_delete_file_stays`. Прежде такую книгу убирали с полки И
  прятали от скана — у Сержа так накопилось 17 файлов, лежащих в папке, которых
  полка не показывает.
- Метка «не возвращать при скане» (`hideFromScan`/`hidePathFromScan`) ставится
  только когда файл оставляют НАМЕРЕННО (`withFiles=false`) или запись склеена с
  дублем. Выхода-пункта в меню нет (убран 12.10.2026 по просьбе Сержа): файл
  удаляют проводником, и запись уходит при скане сама (`dropDeadRecords`, о ней
  говорят вслух). Скан про пропущенное по метке говорит словами:
  «Пропущено: N — эти книги убирали из библиотеки, файлы остались в папке».
- ПРАВИЛО (12.10.2026, решение Сержа: «если запись не имеет файла, мы тыкаем на
  неё — „файла нет“, и система спрашивает, удалить пустую запись или нет. Чтобы не
  было пустых пунктов меню»). ПУСТАЯ ЗАПИСЬ ОТВЕЧАЕТ ПО НАЖАТИЮ: пункта меню для
  уборки нет (`lib_menu_dead` снесён). Тап по строке полки или по строке в
  «недавних книгах» в читалку не пускает: `LibraryActivity.openReader` проверяет
  `BookStore.openable`, говорит «Файла нет: „…“» и спрашивает диалогом — убрать
  запись или оставить (`askRemoveDead` → `removeDead`, запись и кэш). Автоуборка
  при скане осталась как была, вместе с защитой «мёртвой оказалась половина полки —
  не трогаем».

## Системные кнопки в читалке: «скрывать» (07.10.2026)
