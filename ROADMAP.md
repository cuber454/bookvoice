# BookVoice — план переработки (ТЗ от 2026-09-03)

Цель: превратить пошаговую читалку в полноценный библиотечный комбайн
для незрячих (TalkBack). Строим поверх рабочей версии фазами — каждый этап
даёт собранный и тестируемый APK.

## Требования (сводно)

1. Android, только тактильное управление + TalkBack, без визуальных настроек.
2. Стартовый экран настраивается: последняя книга / библиотека.
3. Форматы: TXT, FB2, EPUB, DOCX, PDF (+ желательно больше).
4. TTS: скорость, голос, автоскролл текста при озвучке (вкл/выкл в настройках).
5. Библиотека: сортировки (автор/название/жанр/статус/даты), поиск по названию
   и автору, локальные книги + OPDS-каталоги.
6. OPDS: добавление каталога по URL, просмотр как библиотека, скачивание в офлайн.
7. Построчный обзор через скринридер (ключевое): тап по строке — читает строку,
   свайп вверх/вниз — следующая/предыдущая строка, «Читать с этой строки».
8. Жесты навигации, настраиваются (свайпы для листания).
9. Плеер всегда на экране при открытой книге: Play/Pause, предложение ±, глава ±;
   действия кнопок переназначаются (глава → абзац/страница).
10. Настройки: стартовый экран, скорость/голос TTS, автоскролл, жесты,
    действия кнопок плеера.

## Уже покрыто в v0.2.x

- Пошаговое чтение по предложениям, свайп ±, главы вперёд/назад, строка
  «следующая глава» (п.7, п.9 — в основном).
- TTS: скорость, голоса, переключение движков (п.4 частично).
- Режим непрерывного чтения «Авто» (это и есть автоскролл, п.4).
- Разбор TXT/FB2/ZIP.

## Честная оценка нового

- **Библиотека (п.5)** — самая крупная структурная переделка: сейчас открывается
  одна книга через системный файл-пикер. Нужна полка: список книг, своя позиция
  в каждой, статусы (читаю/дочитал/новая), сортировки. Метаданные (автор/жанр)
  есть в FB2 и EPUB, в TXT — нет.
- **EPUB (п.3)** — новый формат, но простой: zip с XHTML + toc. Реализуемо чисто.
- **Настройки (п.10, п.8)** — отдельный экран: стартовый экран, жесты,
  переназначение кнопок плеера.
- **OPDS (п.6)** — первый сетевой код: Atom/XML-каталог, добавление по URL,
  скачивание. Несложно, но тянет краевые случаи сети.
- **DOCX (п.3)** — zip+XML; иерархия абзацев достаётся с боем, но можно.
- **PDF (п.3)** — самый проблемный для чтения с TTS: без переформатирования;
  скан = текста нет вовсе (нужен OCR); текстовый PDF часто рвёт порядок абзацев.
  Откладываем на конец и с оговоркой о качестве. EPUB/FB2 — природные форматы
  для озвучки.

## Фаза 6 (предложение 15.10.2026, разобрано по читалке Reciter) — ЕДИНЫЙ РАЗБОР КНИГИ

Просьба Сержа: «выбрать самое лучшее из нашего и из ихнего, чтобы не было лишней
путаницы, чтобы это было унифицировано одинаково». Разбор чужой читалки и её
правил — `docs/BACKLOG.md`, разделы про Reciter.

ГДЕ МЫ СЕЙЧАС. Чистка текста вшита ВНУТРЬ каждого парсера: PDF чистится глубоко
(геометрия, разрядка, колонки, колонтитулы, переносы), а fb2/epub/txt идут по
разметке почти без чистки — мусорные строки и рваные фразы в криво
сконвертированной книге остаются. У Reciter после любого парсера идёт ОДИН общий
проход чистки, поэтому fb2 чистится так же, как pdf.

ЦЕЛЬ ФАЗЫ: один конвейер на все форматы.

    файл → парсер (только достаёт текст) → ОБЩИЙ шаг «Разбор структуры» →
    одна модель книги (абзацы + главы + сноски + картинки) → кэш → чтение

ПАРСЕРЫ НЕ ПЕРЕПИСЫВАЕМ И НЕ ВЫБРАСЫВАЕМ: наш разбор fb2 умеет ремонтировать
битые теги и кодировки, чего у них нет; наш PDF умеет геометрию, чего у них нет.

6.1 «РАЗБОР СТРУКТУРЫ» — ОДИН КОД НА ВСЕ ФОРМАТЫ (без модели, мгновенно).
    (а) убрать мусорные строки: одинокий номер страницы, «стр. 12», линейка,
    «downloaded from», ссылка, doi, повторяющийся колонтитул;
    (б) склеить строки, разорванные посреди фразы (дефис + строчная буква), НЕ
    трогая короткие строки подряд — иначе поломаем стихи и эпиграфы;
    (в) разделители сцен (`* * *`, `***`, `• • •`) привести к одному виду;
    (г) заголовки: если в книге уже есть разметка глав (три и больше) — НЕ
    выдумывать; если глав нет — искать по признакам («Глава N», «Часть», короткая
    строка без точки в конце, отдельная строка курсивом), но строки капсом
    заголовками не считать (у Reciter на этом ломалось оглавление — реплики
    героев попадали в главы);
    (д) слишком длинный абзац (от 800 знаков) резать по предложениям — у нас это
    уже делает `ReaderEngine.chunkSpan`, второй раз не делаем.
    СДЕЛАНО к 16.10.2026: (а)-(в) — сборка 261x (`StructureClean.kt` +
    `ParsePrefs.kt`); в PDF заголовки ищутся ещё и ПО КЕГЛЮ — сборка 263x
    (`PdfParser.chaptersFromHeadings`): это и есть «признак» из (г) для форматов,
    где разметки нет вовсе. Абзацы в PDF размечены геометрией (262x).
6.2 КАРТА СООТВЕТСТВИЯ «БЫЛО → СТАЛО» (обязательно). После чистки позиции
    абзацев меняются, а на позициях держатся главы, сноски, картинки, метки и
    МЕСТО ЧТЕНИЯ. Пересчитываем их по карте, как у Reciter `paragraphIndexMap`.
    У них ошибка «большая книга теряет место чтения при открытии» уже была — у
    нас мест чтения много (в каждой книге своё), терять нельзя.
6.3 ОДИН КЭШ И ОДНА ВЕРСИЯ РАЗБОРА. Сейчас кэш `BV6` только у PDF. Делаем общий
    кэш с отпечатком (содержимое книги + версия разбора + настройки): версия
    изменилась — разбор считается заново, место чтения пересчитывается, а не
    теряется.
6.4 ОДНА НАСТРОЙКА ВМЕСТО ГАЛОЧЕК ПО ФОРМАТАМ. Строка «Разбор книги» с тремя
    положениями: «как в файле» / «правила» / «правила и ИИ». Нынешние галочки
    (`expert_pdf_headers`, `expert_pdf_spacing`, `expert_pdf_columns`) уходят под
    неё, чтобы не было двух правд. Рядом — ОДНА строка «Разобрать книгу заново».
    Всё сказанное вслух: что убрано, сколько строк склеено, сколько глав найдено
    — ПО ПРОСЬБЕ СЕРЖА (15.10.2026) САМО НЕ ЗВУЧИТ. Числа живут в СТАТУСНОЙ
    СТРОКЕ разбора (см. ниже, 6.6) и читаются только тогда, когда их спросили
    касанием. При разборе книги читалка молчит совсем.
6.5 ИИ-РАЗБОР — ОТДЕЛЬНАЯ НАДСТРОЙКА, А НЕ ОСНОВА. Включается ТОЛЬКО для книг,
    где правил не хватило (нет оглавления и нет признаков глав), только по кнопке,
    с прогрессом, прерыванием и замером времени; только 64-битные устройства;
    модель ~555 МБ качается отдельно, лицензию принимает владелец. Проверка ответа
    модели обязательна: слова и длина не должны разъехаться, иначе откат к нашему
    разбору (как у MyTTS). В путь открытия книги не попадает НИКОГДА: наше
    открытие — 263 мс, и таким должно остаться.

НЕПРЕДВИДЕННЫЕ СЛУЧАИ, КОТОРЫЕ УЧИТЫВАЕМ ЗАРАНЕЕ: стихи и эпиграфы (не склеивать);
сноски и картинки (карта индексов); книги с одной главой на всю книгу (не
выдумывать); txt без абзацев вовсе (только правила по отступам, иначе модель);
книги, где колонтитул разный на левой и правой странице (повтор + шаблон);
книга, которая уже разобрана хорошо (правило: не трогаем то, что структурно);
слабое устройство (64 бита, память, нагрев).

ПРОВЕРКА ФАЗЫ: «Звонок для родителя» (PDF с колонтитулами), «Блокада Ленинграда»
(своя копия), криво сконвертированный fb2 с рваными строками, книга со стихами,
книга с большим числом сносок. Место чтения до и после — сверить.

ПОРЯДОК: 6.1 + 6.2 (правила и карта) — первая правка, без модели и без трафика;
6.3 — кэш; 6.4 — настройка; 6.5 — проба модели отдельной сборкой, и только по
слову Сержа.

## Фаза 6: КАК ВКЛЮЧАТЬ И ВЫКЛЮЧАТЬ РАЗБОР (предложение от 15.10.2026)

Вопрос Сержа: «что прибавится в настройках, чтобы разбор можно было включать или
отключать». Предлагаю так — и это же снимает путаницу, о которой он говорил.

ОДНА СТРОКА НА ВСЁ. В «Чтении» появляется строка «Разбор книги», значение
выбирается диалогом, текущее значение строка читает вслух: «Разбор книги: правила».
Три положения: «Как в файле» (ничего не трогаем), «Правила» (наш общий разбор, без
модели), «Правила и ИИ» (появится позже, когда будет модель). По умолчанию —
«Правила»: она безопасна, мгновенна и не портит уже размеченное.

НИКАКИХ ВОПРОСОВ И НИКАКИХ ОБЪЯВЛЕНИЙ ПРИ ОТКРЫТИИ КНИГИ. Настройка общая,
применяется молча. ПО ПРОСЬБЕ СЕРЖА (15.10.2026) читалка НЕ ГОВОРИТ, сколько чего
очищено и склеено — ни при первом разборе, ни потом. Чисел очистки нет и в
интерфейсе: они пишутся ТОЛЬКО в журнал (`Diag`), откуда я их вижу, когда Серж
присылает журнал. При разборе книги — тишина.

СТАТУСНАЯ СТРОКА РАЗБОРА (минимум, по просьбе Сержа — «можно посмотреть в статусе»):
короткая строка, из которой видно, ЧЕМ разобрана книга, и только: «Разбор: правила»
или «Разбор: как в файле». Никаких счётчиков вырезанного и склеенного в интерфейсе НЕТ
(см. ниже — они уходят в журнал). Стоит в подменю «Разбор книги»; читается при
обходе, сама не объявляется.

НА КАЖДУЮ КНИГУ — СВОЯ РУЧКА. РЕШЕНО СЕРЖЕМ 15.10.2026: ТОЛЬКО В МЕНЮ «⋮» ЧИТАЛКИ,
когда книга открыта (`MainActivity.showMoreDialog`), и БЕЗ НАГРОМОЖДЕНИЯ — в самом
меню «⋮» появляется ОДИН новый пункт «Разбор книги», а он открывает ПОДМЕНЮ с тремя
строками:
- строка-состояние «Разбор: правила» — БЕЗ ЧИСЕЛ (решение Сержа 15.10.2026: «нужна
  ли нам статистика, сколько вырезано»). Цифры — убрано строк, склеено строк, найдено
  глав — идут ТОЛЬКО В ЖУРНАЛ (`Diag`), где по ним разбираюсь я, когда Серж пришлёт
  журнал. В интерфейсе человеку нужно одно: каким способом разобрана книга. Пассивный
  текст, диктор читает его при обходе подменю, сама по себе строка не объявляется;
- «Разобрать книгу заново» — пересчитать для ОТКРЫТОЙ книги (место чтения при этом
  не сбивается);
- «Вернуть как в файле» — для открытой книги, если чистка не понравилась.
Выход из подменю — системный «назад», как в остальных наших меню («Закрыть» не
ставим). В меню предложения (меню TalkBack «Действия») этих пунктов НЕТ — они не про
предложение, а про книгу. На полке их тоже нет: «⋮» полки — это меню всей полки
(открыть файл, сканировать, сортировка, вид), а не отдельной книги.

ПОД ДВЕРЬЮ (опытные настройки) — ЧАСТИ, А НЕ ВЕСЬ РАЗБОР: три галочки «мусорные
строки», «склейка рваных строк», «поиск глав». Нужны, если какая-то книга
пострадает от одной части: отключаем её, а не весь разбор. Нынешние три галочки
PDF (`expert_pdf_headers`, `expert_pdf_spacing`, `expert_pdf_columns`) остаются
отдельной строкой «PDF: геометрия» — это про разбор PDF, а не про общий шаг.

ПОЧЕМУ ТАК, А НЕ ГАЛОЧКА «ВКЛЮЧИТЬ ИИ-РАЗБОР»: галочка на всё подряд заставляет
человека угадывать, что она делает; три положения говорят, ЧТО именно происходит,
а части под дверью дают выход, если что-то пойдёт не так. Всё, что можно сказать
словами, читалка говорит сама — журнал Серж читать не станет.

## Фаза 6: КАК ВЕДЁМ РАБОТУ (просьба Сержа 15.10.2026)

«Ушёл на полдня — принёс результат, а не по десять раз проверять». Значит:
- Делаем ОДНИМ заходом шаги 6.1-6.4 (правила, карта, кэш, настройка) и собираем
  ОДНУ пробную сборку, а не серию.
- В отчёте — что сделано, где в коде, что проверено, что осталось и что решено
  НЕ делать. Промежуточных сборок не гоняем.
- Если по ходу выяснится, что правка рискованная (например, склейка ломает
  стихи), не гадаем: откладываем эту часть и говорим об этом прямо в отчёте.
- Модель (6.5) в этот заход НЕ входит: сначала правила, потом отдельное решение.

ТЕХНИЧЕСКИЙ ПОРЯДОК (чтобы ничего не забыть):
1. Новый файл `StructureClean.kt`: правила чистки + счётчики (убрано, склеено,
   найдено глав) + карта «было → стало».
2. Врезать ОДНОЙ точкой после парсинга — там, где документ уходит в кэш
   (`BookCache`/`BookStore.openBook`), чтобы все форматы шли одинаково. Второй
   точки входа быть не должно.
3. Кэш: версия разбора `BV6` → `BV7` (константа в `BookCache.kt`), отпечаток =
   версия + настройки + содержимое книги. Старый кэш сам станет негодным — это и
   есть безопасный переход.
4. Прогресс чтения, метки, сноски и картинки пересчитывать по карте при первом
   открытии книги после смены версии разбора.
5. Правила-защиты: не склеивать короткие строки подряд (стихи); строки капсом
   заголовками не считать; не выдумывать главы, если их уже три и больше; абзацы
   из fb2 `<poem>`/`<epigraph>` и строки таблиц помечать флагом «не склеивать».
6. Журнал: каждая книга пишет в `Diag`, что убрано и склеено, версию разбора и
   время разбора (чтобы потом было по чему судить).
7. Откат: тумблеры под дверью, «вернуть как в файле» на книгу и версия кэша.

СВЯЗЬ С БУДУЩИМ ОФОРМЛЕНИЕМ (вопрос Сержа 15.10.2026: «если потом захотим красиво
оформлять — это помешает?»). НЕ помешает, а наоборот: оформление (заголовки, курсив,
эпиграфы, стихи, отступы) — это «как показать», а структура — «что есть»; пока текст
идёт сплошным полотном, оформлять нечего. Поэтому порядок именно такой: сначала
структура, потом оформление. Два условия, которые ставим уже сейчас, чтобы потом не
переделывать: (а) чистка работает на уровне АБЗАЦЕВ и не выжимает текст в плоские
строки, а помечает границы (стихи, эпиграфы, заголовки) флагами; (б) карта «было →
стало» ведёт пометки вместе с текстом, поэтому будущие пометки оформления (курсив,
выделения, цитаты) поедут через неё так же, как сейчас едут сноски и метки. Само
оформление в этот заход НЕ делаем — оно записано отдельно («Вид текста для зрячих»,
`docs/BACKLOG.md`). Чтение вслух от оформления не зависит вовсе.

## Фаза 7 (добавлена 15.10.2026 по слову Сержа) — СТРАНИЦА ИЗ БРАУЗЕРА СТАНОВИТСЯ КНИГОЙ

СТАТУС: ОТЛОЖЕНО 16.10.2026 САМИМ СЕРЖЕМ («тогда давай не будем… Запиши на потом
просто если что») — после честного ответа о качестве разбора веб-страниц. Работы не
начинались, кода нет. Возвращаемся только по его слову; оценка качества и цена —
`docs/BACKLOG.md`, раздел «Поделиться страницей».

Задача: «кидаю страничку из интернета в читалку — она берёт только текст, без ссылок
и мусора». Сейчас так нельзя: манифест принимает ACTION_VIEW/ACTION_SEND только с
ФАЙЛОМ (`LibraryActivity.handleExternalOpen` → `fileUri`), ссылку `http/https` мы не
принимаем вовсе, и человек слышит «файл не получен».

7.1 ПРИЁМ ССЫЛКИ. В манифесте добавить схему `http`/`https` к окну, принимающему
    внешние файлы, и обработать `text/plain` без файла: если в тексте одна ссылка —
    это страница, если текст без ссылки — это выделенный кусок, его тоже читаем.
    Из «Поделиться» и из «Открыть с помощью» — один и тот же путь.
7.2 ЗАГРУЗКА Страницы: okhttp (уже подключён), учёт кодировки и редиректов, предел
    размера, внятная ошибка словами при отсутствии сети.
7.3 ВЫДЕЛЕНИЕ ГЛАВНОГО ТЕКСТА (readability). Выбросить обвязку: меню, шапку, подвал,
    баннеры, кнопки «поделиться», формы, комментарии, рекламу; оставить абзацы и
    заголовки. Ссылки — оставлять их ТЕКСТ, адреса убирать. Картинки и видео не
    читаем. Основа — наш `HtmlParser.kt`, сверху отсев обвязки по простому правилу:
    блок с длинным текстом и знаками препинания — содержимое; блок с обилием ссылок
    и коротких строк — обвязка.
7.4 В БИБЛИОТЕКУ КАК КНИГУ. Результат прогнать общим разбором (фаза 6) и положить
    тем же путём, что книга снаружи (`LibraryImport`), название — заголовок страницы.
    Хранить вместе с адресом, чтобы можно было сказать словами, откуда статья.
7.5 ЧЕСТНЫЕ ОГРАНИЧЕНИЯ — сказать Сержу заранее и повторить в отчёте: страницы,
    собранные скриптами, отдадут пустоту; платный доступ не обойти; у многостраничных
    статей придёт только первая страница; где-то обвязка определится неточно.
